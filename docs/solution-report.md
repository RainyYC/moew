# 解题报告：满足内存约束的 MoE 分块与重叠吞吐优化

> **一句话概括**：把「选网格 → 切层 → 放专家 → 排调度」拆成**可证下界的配置枚举**与
> **多拓扑列表调度 + 空隙回填**两层，在 10 s 墙钟内产出合法且逼近下界的 `SCHEDULE`；
> 关键是**不要漏掉 `K=2V`（DualPipe 镜像配对）这一整类解**——补上它，官方 50 例均值再降 4.0%。
>
> **交付状态**：官方评分集（50 例）**50/50 全部合法通过**，均值 `TIME` 较官方样例解
> **降低 31.1%**（31,765,363 → 21,900,063），50 例逐例更优；判题路径**最大 CPU 7.23 s**（限 10 s）。
> 官方 6 个样例**全部经 CP-SAT 证明为全局最优**。判题核心与官方 `grader.py` 在 50 例上
> **逐例 `TIME` 完全一致**。

## 1. 问题与解法概述

### 1.1 输入与输出

给定集群（`R` 卡、每卡内存 `M`、两种带宽）、模型（`L` 层、每层 `E` 个专家）与逐层负载，
输出四件东西：

| 输出 | 含义 | 约束 |
|---|---|---|
| **网格 `(V, P)`** | `V` = 流水线 stage 数，`P` = 专家并行度 | `V·P ≤ R`（尾卡空闲且**不计内存**） |
| **切层 `ψ`** | `K−1` 个切点，把 `L` 层切成 `K` 块 | `K = V` 或 `K = 2V` |
| **放置 `σ`** | 每层每个专家分到哪个 rank | `σ ∈ [0,P)`，每值恰出现 `E/P` 次 |
| **调度 `SCHEDULE`** | 每个操作在哪个时刻启动 | 满足 §4.2 四条依赖规则 |

目标：最小化一步训练的 `Time`，且每张卡 `M_exp + M_act + M_ovl ≤ M`。

### 1.2 依赖模型（2026-10-29 版，我们逐条对照官方 `grader.py` 校准过）

每个 `(mb, 层)` 有 **4 个前向操作**与 **6 个反向操作**：

```
前向：  s ──────────────┐          （共享专家，不在路由链上）
        disp → gemm → comb

反向：  s_bwd ───────────┐
        comb_bwd → gemm_dx → disp_bwd
        gemm_dw  ← 只等 comb_bwd，可浮动
        s_dw     ← 只等 comb_bwd，可浮动
```

| 操作 | 前驱（层内） | 跨层 |
|---|---|---|
| `s` | — | 等上一层 `comb` |
| `disp` | — | 等上一层 `comb` |
| `gemm` | `disp` | — |
| `comb` | `gemm`, **`s`** | — |
| `s_bwd` | `comb` | 等下一层 `disp_bwd` |
| `comb_bwd` | `comb` | 等下一层 `disp_bwd` |
| `gemm_dx` | `comb_bwd` | — |
| `gemm_dw` | `comb_bwd` | — |
| `disp_bwd` | `gemm_dx`, **`s_bwd`** | — |
| `s_dw` | `comb_bwd` | — |

**这里踩过一个代价很大的坑**：共享专家"与同层解耦"**不等于**完全自由。漏掉
`comb ≥ s`、`disp_bwd ≥ s_bwd`、`s_dw ≥ comb_bwd` 这三条，模型会**退化**并给出"更好"的假结果
——`ex2` 会掉到 3200、`ex3` 掉到 4000，恰好都等于通信引擎下界。**放松依赖必须逐条核对因果是否还能传递。**

### 1.3 与参考实现的定位差异

同期另有一份独立实现（内网 AI，24 例自造 + 50 官方）。两者在六个官方样例上**逐位相同**
（560 / 4880 / 6072 / 3200 / 416 / 1696），技术路线高度重合（LPT 放置、DP 切层、窗口扫描、
列表调度变体、退火/ILS、下界剪枝）。本方案在 50 例上的差异点只有一个但很大：
**把 `K=2V` 当作一等候选**（见策略 1），20/50 例最终选了 `K=2V`。

## 2. 解题流水线

```
输入 → 逐 P 的公共量（pin/pout、m、x、十个时长）       ← 每个 P 只算一次
     → 配置枚举 (P, V, ψ, K)                          ← 静态内存剪枝、下界排序
     → 专家放置 σ（LPT + 换位下降）
     → 列表调度：8 变体 × {early, prio} × 窗口 W      ← 探窗定位 + 大窗口优先
     → 权重梯度旁支延后 + fill_gaps 回填
     → 引擎序列退火（仅小用例）
     → 内存闭区间核算，超限丢弃                        ← 失败时插入 comm_gap 重试
     → 取最优，渲染输出
```

整个搜索由**墙钟预算**驱动：`n_ops > 20 万 → 6.2 s`，`> 2 万 → 7.2 s`，其余 `7.6 s`。

## 3. 核心策略点

> 共 15 条，按「配置 → 剪枝 → 调度 → 工程 → 验证」五组。每条都对照 `solver/` 当前实现核实。

### 3.1 配置枚举与切分（1–4）

#### 1. `K=2V` 镜像配对（本方案的主要增益）

题面允许 `K = 2V`：卡组 `g` 同时持有块 `g`（靠前）与块 `2V−1−g`（靠后），一块跑前向、
另一块跑另一个 microbatch 的反向。**实现只有两处**：`Plan.K` 由切点数推断
（`K = len(psi)+1`，校验 `∈ {V, 2V}`），以及枚举时追加 `2V` 段负载均衡切分。
`group_layers` / `group_of_layer` 本来就是按 `block ≥ V → 2V−1−block` 写的，
所以调度器、内存核算、渲染都不需要改。

**效果**：20/50 例最终选 `K=2V`；均值 **−4.0%**；单例最大 `x05_lr_tight_p6` **−18.3%**。

#### 2. 切层候选：四种 DP + 平移

`dp_split2` 同时最小化 `max_v max(ΣC_v, ΣWc_v)`；另有只按计算、只按通信两个单目标 DP，
以及「按层数均分」和它的 ±1 平移。均分候选是**内存兜底**：把层堆进同一 stage 会让
`M_exp` 超限，均分保证"每 stage 层数最平均"的那个可行解永远在候选集里。

#### 3. `V` 候选：`V_max` 优先，填充异常时才缩小

`V = min(L, 64, R/P)` 让每个卡组少背层、`lb` 最小，代价是填充项 `(nmb+V−1)/nmb`；
两者乘积 `(nmb+V−1)/V` 对 `V` 单调递减，所以**默认取最大**。只有 `2·nmb < V_max`
（填充惩罚 > 2 倍）时才补 `V_max/2, /4, /8, 1` —— 题面并不限制 `nmb` 与 `L` 的组合，
`L=64, nmb=2` 时 `V=64` 的填充是 32.5 倍。

#### 4. 专家放置：LPT + 换位下降

偏斜层上按编号轮转会把热点专家堆到同一 rank，把该层 `m_ℓ` 抬高。本实现按层内负载降序做
LPT（放进当前累计最轻且未满 `E/P` 的 rank），再用一对一交换做下降。`m_ℓ` 是**每层每 rank 的
聚合量**，压低最重 rank 就等于压低整层计算时长。

### 3.2 下界与剪枝（5–6）

#### 5. 下界 `lb` 与更紧的 `lb_chain`

`lb = max_v nmb·max(ΣC_v, ΣWc_v)`：每个卡组两套引擎各自串行完成全部工作量。它忽略
**反向回传链**与**填充**，因此偏松。紧一档的构造是

```
lb_chain = lb + Σ_{v=1..V−1} min_{ℓ∈stage v} disp_bwd(ℓ)
```

即"最后一个 microbatch 的反向必须逐 stage 回穿"。**已验证 50/50 满足 `lb_chain ≤ Time`**，
可用于估算距离（`tools/lb_chain.py`）。

#### 6. 配置剪枝：只剪"静态放不下"

`M_exp` 与 `V, ψ, P` 完全确定，所以"一个卡组要背的层数 × 每层字节 > M"可以直接丢弃候选，
不需要调度。这是唯一无风险的大幅剪枝（同时它让很多小 `P` 自动出局：`P` 越小，
每 rank 的专家越多）。

> **一个反例（已修）**：曾经有一版用 `quick = nmb·max(L·ΣT·F_s, ΣWc)` 并在 `quick < 当前最好下界`
> 时剪掉该 `P`。方向是反的——`quick` 是**高估**量，"它比最好解还小"恰恰说明这个 `P` 有希望。
> 在官方 50 例上实测开关该门控结果**逐位相同**（被它剪掉的 `P` 早已被内存剪枝干掉），
> 但对隐藏用例仍是风险，**已整个关掉**，代价 0.002 s。

### 3.3 调度（7–11）

#### 7. 列表调度：8 变体 × 2 出堆模式 × 窗口

变体是 `(fwd_first, mb_desc, l_desc, l_major)` 四个布尔量的组合；出堆模式为 `prio`（按优先级键）
与 `early`（按最早可开始时刻，堆键惰性修正）。窗口 `W` 控制同时在飞多少个 microbatch
（激活内存约束）。

#### 8. 窗口候选与探窗

`W` 的候选按对数刻度取（`nmb`、`nmb/2`、`nmb/4`…），先用最便宜的组合探 4～12 次定位，
再在定位点附近用完整变体集复扫；定位在 `early` 时把剩余预算全给"更大的窗口 + 该窗口首选模式"。

#### 9. 权重梯度旁支延后 + `fill_gaps` 回填

`gemm_dw` / `s_dw` 只需跟在 `comb_bwd` 之后，因此先强行延后它们、把往返流水打通，
再**回填**到计算引擎已留出的空隙里（`bisect` 维护每个引擎的空闲段）。
这条对 `P=1` 与 `P>1` 都适用，仍走完整内存验收。

#### 10. 引擎序列退火（仅小用例）

从合法调度还原"每个引擎上的操作顺序"，做相邻交换 + 插入的局部搜索，严格更优才接受。
门槛 `n_ops ≤ 2 万`：大用例单次求值 `O(n)`，退火收益抵不过多试几个配置。

#### 11. 内存核算（闭区间口径）与救援

```
M_exp = Σ_层 ((E/P)·Z + Z_s)
M_ovl = U · 峰值(在途通信数)      ← 首尾相接算 2 块
M_act = U_act · 峰值(存活激活数)   ← 闭区间 [comb 结束, s_bwd 开始]
```

内存不满足时不直接放弃：先试"给零时长通信插入 `comm_gap`"，把缓冲峰值拉开再复核一次
——正好卡在边界上的用例靠这一步救回来（`nmb=2` 的紧内存夹具就是这种情况）。

### 3.4 工程与预算（12–13）

#### 12. 预算分档与回退

```
n_ops > 20 万 → 6.2 s     > 2 万 → 7.2 s     其余 → 7.6 s      （内部时钟，另有 0.6 s reserve）
```

预算不是"给得越多越好"：实测 9.2 s 与 7.6 s 的 50 例均值几乎相同（22,884,835 → 22,883,348），
但 CPU 峰值从 8.885 s 降到 7.443 s。**用余量换安全。**

#### 13. 永远有解

枚举 + 搜索全部失败时走有界回退（固定 `P, V`、贪心放置、最简单的调度），保证输出一份合法映射
而不是空文件——题面规定非法/缺失一律 0 分，"差一点"远好于"没有"。

### 3.5 验证（14–15）

#### 14. 三条独立实现互相钳制

- `judge/core`：判题核心（解析 → 时长 → 依赖/引擎 → 内存 → makespan）；
- `solver/formula`：求解器自己的公式与依赖表（与判题核心各写一份，逐项对拍）；
- `tools/independent_check.py`：**第三条**独立实现，不 import 前两者，从题面重新写。

改规则时它最先变红——2026-10-29 那次改动就是它先报错的。此外还有 `tools/cpsat_global.py`
（OR-Tools 全局最优，用于小用例证明）和官方 `grader.py` 双重核对。

#### 15. 与官方判题器逐例对拍

把 50 份输出同时喂给官方 `grader.py` 与本项目 `judge`：

```
一致 50/50
```

1. **50/50 全部优于官方样例解**，均值从 31,765,363 降到 **21,900,063（−31.1%）**，几何平均比值 **0.7309**。
2. **收益分布**：偏结构 / 反向重 / 双块（twochunk）类最大——`r32_p8_ramp` +59.5%、`x07_lr_flat_p10` +58.7%、
   `r24_p4_block` +54.4%、`x13_lr_twochunk_p8` +52.0%、`r16_p4_trap` +46.8%；
   本身已贴近下界的用例收益最小——`x19_vl_trap4_fs4` +1.1%、`x16_vl_trap4_ramp` +6.4%，仍为零回退。
3. **用时**：官方样例解是纯解析模拟（约 0.2 s，无搜索）；本解是完整配置 + 调度搜索，
   均值 **6.33 s**、最大 **7.40 s**，全部 < 10 s 判限，**无超时**。

## 5. 方案优劣与残差分析

### 5.1 优点

- **端到端、无需人工**：从输入直接产出四件套，不做任何用例特判。
- **`K=2V` 不再缺席**：这是本方案与同期的最大差别（20/50 例最终选它，均值 −4.0%）。
- **证明与估计分离**：六个官方样例有 CP-SAT 的最优性证明；50 例只有下界距离，不冒充证明。
- **墙钟安全**：预算分档 + reserve + 有界回退，峰值 7.40 s（限 10 s），零超时。
- **三条实现互相钳制**：判题核心、求解器公式、独立复算器；改规则时独立那条最先红。
- **判题器与官方逐位等价**：50/50 一致，不存在"本地合法、官方非法"的风险。

### 5.2 缺点与已知局限

- **调度是贪心 + 局部搜索，非全局最优**：只有 6 个官方样例有最优性证明；
  `nmb ≥ 4` 的中大用例状态爆炸，无法穷举。
- **`lb` 偏松**：中位数 `Time/lb = 1.268`，加"反向回传链"后 `1.250`；剩余差距主要来自
  **填充**（`nmb < V` 时前向波铺不满）与**层内链**，不是调度器低效。
- **对偏斜 + 填充型用例仍弱于参考实现**（`x19`、`r16_p4_trap`）。
- **`fill_boost` 与逐引擎序列 ILS 尚未实现**：这是目前唯一已知有第三方实测支持、
  而我们没有的能力。

### 5.3 精度证据汇总

| 结论 | 证据 | 强度 |
|---|---|---|
| 六个官方样例的 `Time` 是全局最优 | CP-SAT 枚举全部决策 | **已证** |
| ex3 = 6072 | CP-SAT + 独立穷举（不用 OR-Tools，枚举 317 万种引擎次序，并复现题面自己的 `P=4 → 76800` 对照） | **已证（两法）** |
| 50 例判题结论与官方一致 | 官方 `grader.py` 逐例对拍 | **已证** |
| 50 例距最优多远 | 只有 `lb` / `lb_chain`（均 ≤ 真实 makespan，已验证 50/50） | **未证** |
| `K=2V` 带来 −4.0% | 官方 50 例同机同判题器前后对比 | **实测** |

### 5.4 残差结构分析

对 50 例的最终解计算 `lb` 与 `lb_chain`：

| 判据 | 中位数 | ≤1.10 | ≤1.20 | ≤1.50 |
|---|---|---|---|---|
| `Time/lb` | 1.268 | 16/50 | 21/50 | 34/50 |
| `Time/lb_chain` | **1.250** | 17/50 | 23/50 | 37/50 |

**`Time/lb` 的大值应解读为"朴素下界不可达"，而非方案低效**，原因有两类：

1. **填充绑定**（`nmb < V`）：前向波根本铺不满 V 个 stage，`nmb·seg` 项高估了可用并行度；
2. **引擎占用绑定**（`nmb ≥ V`）：依赖链不是瓶颈，差距来自两套引擎的忙碌时间无法再压缩。

距离最大的几例：`x14`（3.00）、`x11`（2.35）、`x10`（2.25）、`x19`（2.09）、`x12`（1.99）、
`r20`（1.96）。它们的共同点是 **`nmb < V`**（例：`x14` 是 `nmb=6, V=10`；`x11` 是 `nmb=12, V=16`），
即前向波铺不满流水线——填充绑定。

对其中三例做过全 `(P, V, ψ, W, 模式, 变体)` 穷举：`x14`/`x19` 与现解**逐位相同**，`x11` 只好 0.05%。
即这些残差**在当前调度族内不可兑现**。（需要说明：这只证明"这族列表调度取不到"，
不等于"全局最优就是这个值"——后者没有证明。）

### 5.4A 评估过但否决的改动

| 候选改动 | 假设 | 实测 | 结论 |
|---|---|---|---|
| **用 `lb` 指导切分**（而不是只做剪枝） | 最小化 `engine_lb` 应让尾部 stage 少分层 | `lb` 忽略反向回传链，按它优化会把层分给尾部，而尾部恰是回传链最长的地方 | **否决**。下界只能证明"到顶"与安全剪枝，不能指导配置 |
| **加大预算到 9.2 s** | 更多时间 → 更好解 | 50 例均值 22,884,835 → 22,883,348（几乎不变），CPU 峰值 8.885 s | **否决**。改为 7.6 s，用 1.4 s 余量换安全 |
| **缩小 `V`**（`V/2`、`V/4`） | 减少填充气泡 | `V=32` 的 `Time/lb` 是 1.23（看似优于 1.41），但**绝对**时间是 `1.21e13`，比 `V=64` 的 `6.91e12` 差 74% | **否决**（除 `2·nmb < V_max` 的极端填充情形） |
| **对大用例开序列退火** | 局部搜索总能改进 | b01（65 280 op）跑 38 s，**一步未降**；单次求值 `O(n)` 把预算吃光 | **否决**。门槛保持在 2 万 op |
| **拿 `Time/lb` 跨网格比较** | 比值低就更好 | 比值随 `V` 变化（`lb` 本身变），跨网格比较会选出绝对更差的解 | **禁止**，只比绝对 `Time` |
| **`quick` 那个 `P` 门控** | 省时间 | 方向反了（`quick` 是上界）；官方 50 例上开关结果逐位相同 | **关掉**（风险 > 收益） |

### 5.4B 本次两项优化的量化

| 优化 | 改动量 | 50 例均值 | 单例最大改善 | 风险 |
|---|---|---|---|---|
| `K=2V` 镜像配对 | 两处（`Plan.K` 推断 + 枚举追加） | 22,883,348 → **21,900,063**（−4.3%） | `x05_lr_tight_p6` −18.3% | 低（`min(K=V, K=2V)` 兜底，数学上不劣化） |
| `P` 门控方向修正 | 一行条件 | 不变（±0） | — | 修正后**删掉**，消除隐藏用例风险 |

```
solver/
  casein.py     输入解析（含负载向量、范围校验）

  psi.py        切层：dp_split2 / 单目标 DP / 均分 / 平移
  place.py      专家放置：LPT + 换位下降
  sched.py      列表调度（变体/窗口/空隙回填）、内存核算、渲染、`check_schedule`
  solve.py      配置枚举（含 K=2V）、探窗、预算分配、退火、回退
  solve_all.py  CLI（单例 / 批量 / 自检），按 op 数自动选预算
judge/
  core/         解析、时长、依赖/引擎检查、内存、makespan（与求解器各写一份）
  service/      HTTP 服务、队列、账本、SSE、自检
tools/
  cpsat_opt.py / cpsat_global.py   OR-Tools 全局最优（小用例）
  ex3_verify.py                    不用 OR-Tools 的独立穷举复核
  independent_check.py             第三条独立实现
  lb_chain.py                      下界距离分析
  gen_battery.py / large_sweep.py / fuzz.py
bigcases/battery/   13 个大用例（最大 64 万 op）
cases/              官方 7 例（ex1–ex6 + mini）
official/           官方包（判题器 + 50 例 + 参考报告）
```
