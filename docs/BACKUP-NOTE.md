# 备份目录说明（请勿当作当前实现）

这三个目录是**规则变更前的快照**，仅用于对照"改规则改坏了什么"。当前实现以根目录的
`judge/`、`solver/`、`cases/` 为准。

| 目录 | 快照时间 | 对应的题面 | 为什么留着 |
| --- | --- | --- | --- |
| `cases-v2-backup/` | 2026-10-26 | problem-v3（网格 `V P D`、`s` 未解耦） | 想回看旧样例/旧期望值时用 |
| `judge-v3-backup/` | 2026-10-29 | problem-v3 | 同上 |
| `solver-v3-backup/` | 2026-10-29 | problem-v3 | 同上 |

**重要差异**（用这些目录里的代码跑新样例会得到错误结论）：

1. 输出首行：旧版 `V P D`，新版 `V P`。
2. 网格约束：旧 `V·P·D = R`，新 `V·P ≤ R`。
3. 依赖表：旧版共享专家串在链上（`s→disp`、`s_bwd→comb_bwd`），新版解耦但补了
   `comb ≥ s`、`disp_bwd ≥ s_bwd`、`s_dw ≥ comb_bwd` 三条。
4. 六个官方样例的 `SCHEDULE` 全部重写过，旧样例的 Time 是 `592/4880/7000/3200/416/1744`。

确认无误后可以直接删掉这三个目录（它们不参与任何测试）。
