# C++ 编码规范

维护源码按职责拆分在 `src/` 下的 C++17 头文件和实现文件中。`src/solver.cpp` 只定义全局 `main`；`src/sources.mk` 是多翻译单元构建及可选单文件导出共用的唯一 `.cpp` 源清单。日常使用 `make -j2 build` 增量编译对象与依赖文件，再以 `-flto` 链接为 `build/solver`；`make submission` 可确定性地导出自包含 `submission/solver.cpp`，`make submission-check` 检查它是否过期。单文件导出与多翻译单元构建使用相同模块源码，但不要求生成逐字节相同的二进制。标准库头文件在 `src/common.hpp` 显式列出；模块使用项目本地 include。统一使用四空格缩进、每行约 100 列、控制语句加花括号、一行一条语句，并遵循仓库 `.clang-format`。

类型使用 `PascalCase`；函数、方法、局部变量及成员使用 `snake_case`。为便于核对题目公式，`P`、`V`、`L` 等问题域符号可保留原样，并在不直观处就近说明。按功能将代码分成清楚的区域，把输入解析、搜索阶段和输出等职责放进具名函数。注释记录约束、精确语义和比较规则，不复述显然的语法。

调度器调用使用 `scheduling::ProblemView`、独立的 `EventConfig`/`ListConfig` 和 `ScheduleOutput`，以字段名表达策略选择，避免长串位置参数。`ProblemView` 对大向量只保存 const 引用。搜索阶段通过 `Scheduler<ConcreteStrategy>` 在编译期选择策略；不要增加虚函数/`std::function`，也不要把策略派发放进节点或候选内循环。调度适配应发生在完整调度调用边界，并保持原内核与现有候选剪枝、内存检查顺序。具体参与者和扩展例子见[设计模式说明](design-patterns.md)。

所有运算保持精确整数语义，包括有符号 128 位计算。内存检查遵循官方闭区间：区间端点相接时仍然重叠。若某组所有通信时长均为零，该组通信 buffer 不计入内存。local polish 的内存快路径只有在逐组证明固定驻留量、最多两个闭区间通信 buffer、至多 `layers * mb` 个激活区间之和不超过 `M` 时才可启用；其他组必须执行完整峰值检查。候选仅在 `Time` 严格下降时替换；local polish 允许 `Time` 相等且操作结束时间总和下降时移动。重构必须保持遍历顺序、比较/tie 规则、命令行语义及绝对截止时间。局部搜索扩展预算固定为 9200 毫秒；截止检查在工作单元之间协作执行，预处理与单次候选评估仍须控制运行时间。命令行只公开有限模式选择和诊断选项，未知参数必须明确报错。
