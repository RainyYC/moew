## 3. 穷举是否真的在跑（独立复算）

我用**自己写的**枚举器（不 import `solver`，按题面 §4.2 建 40 个操作的依赖边，再把每个 stage 两条 mb 链的通信序列边加进去，做 Kahn 环检测）：

| 用例 | 空间（solver 统计） | 我的独立复算 | 可行（solver） | 我的独立复算 | 死锁 |
|---|---|---|---|---|---|
| ex2 | 4900 | **4900**（70×70，70 = C(8,4)） | 2554 | **2554** | 2346 |
| ex6 | 4900 | **4900** | 2554 | **2554** | 2346 |
| ex1/ex3/ex4 | 70 | 70（单 stage，C(8,4)） | 70 | 70 | 0 |
| ex5 | 1 | 1（P=1，通信全零时长 → 每条链为空） | 1 | 1 | 0 |

`2554 + 2346 = 4900`，与 solver 的 `feasible/space` 完全吻合；这说明"可行数"就是"依赖边 ∪ 序列边无环"的配对数，不是别的口径。

**抽 3 个被判死锁的配对核对环**（每个环上的边都能归类为依赖边或序列边）：

1. stage1 序列 `[0:1:disp, 0:1:comb, 0:1:comb_bwd, 1:1:disp, 0:1:disp_bwd, 1:1:comb, 1:1:comb_bwd, 1:1:disp_bwd]`
   环：`0:0:s_bwd →（依赖）0:0:comb_bwd →（依赖）0:0:gemm_dx →（依赖）0:0:disp_bwd →（序列）1:0:disp →（依赖）1:0:gemm →（依赖）1:0:comb →（依赖）1:1:s →（依赖）1:1:disp →（序列）0:1:disp_bwd →（依赖）0:0:s_bwd`。
2. 同上但 stage1 把 `1:1:comb` 放在 `0:1:disp_bwd` 之后：环多经过 `1:1:gemm → 1:1:comb`，仍是"`0:0:disp_bwd` 先于 `1:0:disp`"+"`comb(1,0)` 先于 `s(1,1)`"与回程依赖互锁。
3. stage1 序列 `[…, 1:1:comb_bwd, 0:1:disp_bwd, …]`：环经过 `1:1:s_bwd → 1:1:comb_bwd → 0:1:disp_bwd`，同样成立。

三个环的共同结构：stage0 的 `disp_bwd` 被序列推到 `1:0:disp` 之前，而 `1:1:s` 又依赖 `1:0:comb`，`0:1:disp_bwd` 又依赖 `1:1:comb*`，最终 `0:0:s_bwd` 依赖 `0:1:disp_bwd` 形成闭环——**是真死锁，不是贪心"转不动"**。因此没有"剪枝把可行解误杀"的情况（至少在这 3 个抽样上；2554/4900 的计数完全一致也支持这一结论）。

## 6. 观察（不构成 finding）

- **O1**：`exact.py:_simulate` 的 `if best_idx < 0: return None` 上方注释写"`pragma: no cover - 依赖图无环，不会发生`"，**实际它就是死锁检测点**（ex2 的 2346/4900 个配对会走到这里）。只是注释过时，行为正确。
- **O2**：`exact` 找到更优解后的渲染/落盘路径（`outcome is not None` → 新 `_Best`）**没有被任何用例覆盖**：6 例全部"无改进"，退化形态自测也不跑 `--exact`。不是缺陷（否定结论不依赖它），但该分支属于未验证代码。
- **O3**：`--exact` 只能放在位置参数之后；放最前会被当成批量模式的 argparse 选项而报 2。文档用法一致，但和 `--budget` 的直觉（可放前）不同，容易误用；建议在 `_SINGLE_USAGE` 里把顺序写清（已写 `<case.in> [case.out] [--budget 秒] [--exact]`，够用）。
- **O4**：NOTES 声明"耗时随机器浮动 ±10%"，实测 ex1 的 elapsed 偏差约 −19%（1.13 vs 1.4）、ex3/ex4 的 wall 0.07 vs 0.02；量级与结论不受影响，但"±10%"略乐观。
- **O5**：第二阶段只对第一阶段最好的 4 个通信交错做计算线性扩展（`PHASE_B_SEEDS = 4`），NOTES §9 已明确说这是**部分覆盖**（完整联合枚举 3.1×10^7 没跑），属于已知边界而非隐藏剪枝。
