赛题介绍

满足内存约束的 MoE 分块与重叠吞吐优化

1. 背景

在大模型训练中，MoE（Mixture of Experts）层把「一份大 FFN」换成 E 个小专家：每
个 token 只被路由到少数几个专家，由这些专家所在的 NPU 完成计算。这样可以在算力
基本不变的前提下把参数量放大一个数量级；代价是数据要流动：token 必须先被送到专
家所在的卡上，算完再送回来。

为了让集群跑得快，系统通常同时使用两种并行方式：

  • 专家并行（Expert Parallelism, EP）：把同一层的 E 个专家分到不同的 NPU 上。
    token 通过 AllToAll 被送到目标专家所在的卡，算完再 AllToAll 回来。
  • 管线并行（Pipeline Parallelism, PP）：把 L 层切成若干段（stage），
    microbatch 像流水线一样依次流过各段。DualPipe 等方案会让 microbatch 从两端
    同时注入，以减少空泡。

这两件事互相纠缠：EP 决定 AllToAll 走节点内还是跨节点（两者带宽往往差一个数量级
），PP 决定哪些层在同一张卡上、以及流水线的空泡有多少；而每张卡的 HBM（高带宽内
存）是硬上限，专家参数、通信缓冲、激活值都抢同一块内存。

本题： 给定集群拓扑、每卡内存、模型规模与逐层负载，输出一份完整映射（网格、切层
、逐层专家放置、整步调度），使一步训练的 wall-clock time 最小，且每张卡均不超过
内存上限。

问题难点

三层决策耦合在一起：

  • 网格 (V,P,D)：stage 数、专家并行规模、数据并行度。它决定每卡驻留几个专家（
    每层 E/P 个），专家参数占多少内存由此而来；通信对端分布在几个节点上也由它决
    定，因而决定了流量走节点内还是跨节点。
  • 切层 ψ：L 层怎么连续切成 V 段。它决定哪些层共卡，因而决定每张卡的内存预算，
    也决定最慢的 stage 有多慢。
  • 调度：通信与计算在时间轴上如何交错。它决定全部重叠与空泡，也决定某一时刻还
    有多少缓冲与激活没有释放。

总运行时间取决于几个互相牵制的瓶颈：最挤的通信边、最慢的 stage、最长的依赖操作
链。内存上限又进一步限制哪些配置可行。四项决策（网格、切层、专家放置与调度）因
此同时作用于时间与内存，必须一起定下来，不能一项接一项地先后求解。

商业价值

MoE 是主流大模型的核心结构，EP/PP 联合映射直接决定训练吞吐与显存占用。自动化的
映射与调度搜索可降低大模型训练对专家调参的依赖，为 AI 编译器与集群调度栈提供可
复用的布局与调度能力。

1.1 一次前向的四个步骤，与重叠从何而来

一个 MoE 层在每张卡上的前向过程包含四个步骤：

 1. 共享专家：所有 token 都经过它。纯计算，不涉及跨卡通信。
 2. 分发 AllToAll：把本地 token 按路由结果发给目标专家所在的卡。纯通信。
 3. GroupGEMM：计算落在本卡的专家。纯计算。
 4. 汇集 AllToAll：把专家的输出送回 token 原来的卡。纯通信。

反向对应地产生六个步骤：共享专家的输入梯度与权重梯度、专家输入梯度与专家权重梯
度，以及分发与汇集各自的反向通信。

前向与反向合起来，每张卡上的每一层共十个步骤。 关键点在于：每个 NPU 的通信能力
与计算能力都是固定的，通信走通信引擎，计算走计算引擎，两者可以同时进行。第 4.1
节给出每个步骤占用的引擎与时长，第 4.2 节给出它们之间的依赖；运行时间上的收益，
正来自在满足这些依赖的前提下设计重叠。一层的十个步骤并不是一条链：反向分成一条
输入梯度路径和两个权重梯度步骤，后者只需跟在来的梯度之后。所以除了不同
microbatch、不同层之间的交错，还可以把一层的权重梯度步骤滑进另一层的空档里，从
中再挤出重叠。

已有文献中出现过三种经典排法。 它们都能用本题的输出格式表达，但我们允许更一般的
调度：参赛者提交的是一份完整调度，三种排法只是它的特例。

  • 1F1B（一次前向、一次反向）：流水线填满之后，每个 stage 在新 microbatch 的前
    向与较旧 microbatch 的反向之间来回切换，前向与反向两侧都保持忙碌，同时在飞
    的 microbatch 数保持有界。见 PipeDream [3]。
  • ZB1P（把反向拆开、把其中较轻的一半滑出去）：第 4.2 节第 1 条把一层的反向拆
    成输入梯度路径 s_bwd → comb_bwd → gemm_dx → disp_bwd 与两个权重梯度步骤 
    gemm_dw、s_dw，后者只需要来的梯度。路径本身串成一条链，两个权重梯度步骤却可
    以放在 comb_bwd 之后的任意位置，因此能挪到计算引擎本来空闲的时刻。第 2 条把
    相邻层的反向锚定在 disp_bwd，即输入梯度路径的末端，这种推迟于是成为结构性的
    ，而不只是被允许：把权重梯度往后推不会拖慢任何其他层。见零气泡流水线工作中
    的 ZB-H1 排法 [2]。
  • DUALPIPE（一张卡上放两块）：K=2V 时一个卡组持有块 k 及其镜像 2V−1−k，一块于
    是可以跑前向，另一块同时跑另一个 microbatch 的反向；K=V 时一张卡只持有一块
    ，这种排法无从谈起。见 DeepSeek-V3 报告中的 DualPipe 排法 [1]。

为了让题目可控，我们做了若干简化。 操作是原子的：不允许 tile 级切块，因此第 4.1
节的任何操作都不会被拆成几部分（见 3.2 节）。AllToAll 与 GroupGEMM 也不会融合进
同一个 kernel（与 UniEP [4] 不同），因为融合要求在载荷完全到达之前就消费它（第
4.2 节第 1 条）；同理，共享专家只能跨 microbatch 与通信重叠，不能在同一个
microbatch 内重叠。负载分布固定且已知：aℓ,e 在整步中不变，一份调度在开始前就声
明所有开始时刻，而不是在运行时自适应。最后，计算与通信互不拖慢：每个操作的时长
恰好如第 4.1 节所述。

2. 输入

所有量均为非负整数，同一行以空白分隔。

本题不模拟真实时钟：所有时间量都以同一个抽象「时间单位」计，Time 的绝对数值没有
物理含义，只用于排名比较。带宽 Bin,Bout 的单位是字节/时间单位，时间系数 Fs,F
io,Fin 的单位是时间单位。

第 1 行 N S M Bin Bout：集群与内存。

| 符号 | 含义 |
| --- | --- |
| N | 节点数 |
| S | 每节点 NPU 数；总卡数 R=N⋅S |
| M | 每卡 HBM 上限（字节） |
| Bin | 节点内带宽（字节/时间单位）。同节点通信都走它，通常远大于跨节点带宽 |
| Bout | 节点间带宽（字节/时间单位），Bout≤Bin |

第 2 行 L E Z Zs U Uact k nmb Fs Fio Fin α× β×：模型规模、缓冲与时间系
数。

| 符号 | 含义 |
| --- | --- |
| L | MoE 层数 |
| E | 每层可路由专家数（逐层相同） |
| Z | 单个可路由专家参数大小（字节）。每卡每层驻留 E/P 个专家，故每层占用 (E/P)Z 字节 |
| Zs | 共享专家大小（每卡每层一份，可为 0） |
| U | 一块通信缓冲的字节数。每个卡组只有一套通信引擎（4.2 第 3 条），同一时刻每张卡最多有一个通信操作在途，占用 U 字节；见 4.6 |
| Uact | 一个 (microbatch, 层) 的激活值字节数；见 4.6 |
| k | 每个 token 路由到的专家数（top-k，逐层相同） |
| nmb | microbatch 数（偶数）。它决定流水线里同时推进多少个 microbatch |
| Fs | 共享专家时间系数（每 slot）：共享专家处理一个 slot 需要多少时间单位 |
| Fio | AllToAll 通信系数（每单位带宽时间的时间单位，见 4.4） |
| Fin | GroupGEMM 计算系数（每 slot 占用多少时间单位，见 4.3） |
| α×,β× | 反向系数（微单位）：α=10−6α×，β=10−6β×。这两个系数决定前向、反向以 及反向中权重梯度部分的相对耗时；具体乘在哪一步见第 4.1 节 |

第 3 行 d b：隐层宽度（元素数）与元素字节数。每个 token 的激活为 d⋅b 字节，分摊
到它路由的 k 个专家上，因此每 slot 发往一个对端的载荷是 H=⌊db/k⌋ 字节。

第 4 行起共 L 行，每行描述一层的负载。第 ℓ 行为 Tℓ 与可选负载向量：

  • Tℓ 是层 ℓ 的 token-slot 数（top-k 已展开，即 Tℓ=k⋅Bℓ，其中 Bℓ 是该层
    token 数）。
  • 若该层负载均衡，该行只写 Tℓ。
  • 否则在其后写 E 个整数 aℓ,0…aℓ,E−1，表示路由到各专家的 slot 数，满足 ∑eaℓ
    ,e=Tℓ。

注意，输入给出的负载分布是静态的：每层每个专家分到多少 slot 在输入里已经确定，
不随训练步变化。建模时也不假定它均匀：真实训练中门控输出天然偏斜，各层的偏斜程
度还各不相同。负载既已知，专家怎么放（见 4.3 节）就成了一个可以据此优化的决策。

3. 输出

按以下格式输出完整映射：

V P D
PSI
K ψ_1 ψ_2 ... ψ_{K-1}
MAP
σ_0,0 σ_0,1 ... σ_0,E-1
...
SCHEDULE
t mb:ℓ:op mb:ℓ:op ...
...

3.1 逐字段说明

| 字段 | 含义 |
| --- | --- |
| V | 管线 stage 数（沿层切分） |
| P | 专家并行规模（同一层专家切到几个 rank）。须满足 P∣S 或 S∣P，以保证 EP 组与节点对齐（见 4.4 节） |
| D | 数据并行度（V⋅P⋅D=R） |
| PSI | 块数 K，紧跟在同一行后面的是 K−1 个切点 ψ1,…,ψK−1，严格递增。K 只 能取 V（每个卡组一块，默认）或 2V（每个卡组两块），其他取值一律非法 ；K=1 时该行只写块数 1，不带切点。块 k 含层 [ψk,ψk+1)；块 k 属于卡组 g(k)=k（k<V）或卡组g(k)=2V−1−k（k≥V），即镜像配对。因此K=2V时，每个卡组各持一块靠前的块和一块靠后的块 |
| MAP | 逐层专家放置，共 L 行。第 ℓ 行是 E 个整数 σℓ,e∈[0,P)：专家 e 放在本EP 组的第几个 rank。每个取值恰好出现 E/P 次 |
| SCHEDULE | 整步调度，见下 |

网格与物理卡。 V、P、D 由参赛者选择，三者一起决定流水线有多少个 stage、一个 EP
组有多宽、有几个数据并行副本。参赛者选择不了的是 V×P×D 这块网格如何嵌入物理卡：
给定这三个数，评测器按固定规则 q=v⋅(P⋅D)+d⋅P+p 嵌入（p 最快变）。哪连续 P 张卡
构成一个 EP 组、每个 stage 的卡块落在哪里，都由这条规则决定，因此物理卡 q 就是
网格坐标 (v,d,p) 对应的那张卡：一个 EP 组的 P 个 rank 是连续的卡，每个 stage 占
一段连续的 P⋅D 张卡。又因为 P∣S 或 S∣P，一个 EP 组要么完全落在节点内，要么整齐
地跨节点，4.4 节的节点内对端数因此是确定的。共用同一个 stage 的那 P⋅D 张卡称为
一个卡组：它拥有该 stage 的层，也是计算引擎占用与内存的核算单位（见 4.2 与 4.6
节）。

3.2 调度格式

调度是一张时间表。每一行是一个时刻，行首是整数时刻 t，其后是若干个操作，写作 
mb:ℓ:op：

  • mb 是 microbatch 编号，范围 [0,nmb)；
  • ℓ 是层号，范围 [0,L)，它属于哪一块由 PSI 行声明的块数 K 与切点决定，而
    stage 就是拥有该块的卡组，因此条目里不必再写 stage；
  • op 是操作名，取自 4.1 节的十种。

同一行内的所有操作在同一时刻开始并发执行。 每层恰好有第 4.1 节的十个操作，每个
microbatch 各一次；十个之外的操作名一律非法。

调度写的是每个卡组一张代表卡的动作，因此一份调度里共 V 张代表卡。一个卡组里的 P
⋅D 张卡在调度意义下等价：各自负责自己的专家分片和自己的数据，组内其余每张卡都跟
随同一份调度。条目给出开始时刻和三元组 mb:ℓ:op：在该时刻，拥有层 ℓ 的卡组在其全
部卡上为 microbatch mb 同时执行该层的操作 op。每个 (microbatch, 层, 操作) 三元
组在清单里恰好出现一次。

一个条目由哪个卡组执行，取决于层号和 PSI 行：行里的切点把 L 层切成 K 块。K=V 时
每个卡组持有一段连续的层，卡组 k 就持块 k；这一段同时服务其中各层的前向与反向，
一个 microbatch 的前向会依次访问每个卡组。K=2V 时块到卡组按镜像配对：块 k 属于
卡组 k（k<V），或属于卡组2V−1−k（k≥V）。于是每个卡组拥有模型的两块，一块来自层区
间前半、一块来自后半，两块的参数都驻留在它的卡上；这两块一块靠近层序开头，一块
靠近末尾。前向从开头走向末尾，反向则相反，因此稳态调度可以用年轻microbatch的前
向占据靠前的那块，用较旧microbatch的反向占据靠后的那块，让该卡组的两套引擎同时
为两个不同的microbatch工作。这正是DUALPIPE一类调度利用的性质。此时流水线有2V块
深，一个microbatch的前向会访问每个卡组两次。

对输出的约束：

 1. t 必须非降，调度按时间顺序书写。
 2. 同一行内不得出现两个占用同一引擎的操作（具体规则见 4.2）。
 3. 行与行之间不必等距：某一行写完，直接写下一个有新操作的时刻即可。

一个最小的完整例子（对应 7.1 节）：

1 2 1
PSI
1
MAP
0 1
SCHEDULE
0 0:0:s
16 0:0:disp
86 0:0:gemm
110 0:0:comb

说明：时刻 0 开始共享专家（时长 16），时刻 16 开始分发（时长 70），时刻 86 开始
GroupGEMM（时长 24），时刻 110 开始汇集（时长 70）。最后一次操作在 110+70=180 
结束，故 Time=180。

4. 得分计算（模拟过程）

4.1 十种基本操作

每个操作占用两套引擎中的一套，时长取下表中的一个表达式。表达式由每层的三个量 mℓ
、xℓ、sℓ（定义见 4.3 与 4.4 节）和几个全局系数算出。

| 操作 | 引擎 | 时长 | 含义 |
| --- | --- | --- | --- |
| s | 计算 | sℓ | 共享专家前向 |
| disp | 通信 | xℓ | 分发 AllToAll |
| gemm | 计算 | mℓFin | 落在本卡的专家前向 |
| comb | 通信 | xℓ | 汇集 AllToAll |
| s_bwd | 计算 | αsℓ | 共享专家输入梯度 |
| comb_bwd | 通信 | αxℓ | 汇集反向 |
| gemm_dx | 计算 | αmℓFin | 专家输入梯度 |
| gemm_dw | 计算 | αβmℓFin | 专家权重梯度 |
| disp_bwd | 通信 | αxℓ | 分发反向 |
| s_dw | 计算 | αβsℓ | 共享专家权重梯度 |

所有时长向上取整为整数。前向拆成四个步骤、反向拆成六个步骤，是为了让通信与计算
能以单个步骤为粒度重叠。系数决定这些步骤的相对长度：反向的四个输入梯度步骤是各
自前向步骤的 α 倍，两个权重梯度步骤再乘一层 β，因此一次反向约等于 α(1+β) 次前向
，其中权重梯度占 β/(1+β)。

4.2 依赖与资源

合法调度必须满足：

 1. 层内依赖：同一 (microbatch, 层) 的前向顺序固定为
    s → disp → gemm → comb。反向不是一条链：它由输入梯度路径
    s_bwd → comb_bwd → gemm_dx → disp_bwd 与两个权重梯度步骤 gemm_dw（专家权重
    梯度）、s_dw（共享专家权重梯度）组成；路径中每一步都跟在它前一步之后，两个
    权重梯度步骤则只需要来的梯度，也就是只需跟在 comb_bwd 之后，与同层其他步骤
    无关。一个步骤只能在它所跟随的步骤完成之后开始，因此 comb_bwd 一结束，两个
    权重梯度步骤就可以放在该层反向的任意更晚位置，调度能把它们推迟到计算引擎本
    来空闲的时刻。一个 (microbatch, 层) 的反向只在其前向完成后才开始：s_bwd 不
    得早于同一 (microbatch, 层) 的 comb 结束。
 2. 管线依赖（层序）：同一个 microbatch 内，激活逐层向前流动，梯度沿同样的路径
    反向流回。层 ℓ 的第一个前向操作（s）要等层 ℓ−1 的前向完成，即在它的 comb 之
    后，对每个 ℓ≥1 成立；层 ℓ 的第一个反向操作（s_bwd）要等层 ℓ+1 的反向送出输
    入梯度，即在它的 disp_bwd 之后，对每个 ℓ≤L−2 成立；这还要叠加第 1 条中 
    s_bwd 对本层 comb 的依赖。锚点取 disp_bwd，而不是层 ℓ+1 反向的最后一步，因
    为层 ℓ 只消费梯度：层 ℓ+1 在 disp_bwd 之后做的都是它自己的权重梯度，下游没
    有东西读它，也就拖不住层 ℓ。两条陈述都建立在层上而不是块上：它们同样约束共
    用一个卡组的两层，因此不必在它们之上再加块一级的陈述。
 3. 资源互斥：一个卡组有一套计算引擎和一套通信引擎（见 3.1 节）。任一时刻它最多
    运行一个计算类操作和一个通信类操作；K=2V 时这条限制同时覆盖它的两块，两块的
    操作因此争用同一对引擎。
 4. 因果性：条目声明的 t 不得早于其依赖的完成时刻；违反则该映射非法。

这四条规则就是全部的调度约束：参赛者不限于 1.1 节介绍的经典排法，任何满足 4.2
的调度都可以提交。

4.3 负载、放置与计算时间

每层每 rank 放 E/P 个专家（放哪几个由 MAP 决定）。记 rank r 在本层承载的 slot
数

Lℓ,r=e: σℓ,e=r∑aℓ,e,mℓ=rmaxLℓ,r.

计算类操作的时长取决于该层所在 EP 组内最慢的那个 rank，所以取 mℓ 而不是平均值
：某个 rank 上的专家越热，整层就得等它。

若某层的输入行不带负载向量，评测器先把它 Tℓ 个 slot 尽量均匀地分给 E 个专家，
再算 mℓ，于是各专家分到的 slot 数至多相差 1。负载均衡时 mℓ=⌈Tℓ/P⌉，与常规公
式一致。负载偏斜时 mℓ 还取决于 MAP：把热点专家分散到不同 rank，就能压低 mℓ。
注意通信量 Xℓ 只依赖总量 Tℓ（见 4.4），所以偏斜只抬高计算、不改变通信，两类引
擎对偏斜的敏感程度并不相同。

4.4 通信时间

每 rank 每层发往本 EP 组内其余 P−1 个 rank 中每一个的字节数为

Xℓ=⌈TℓHPP−1⌉,H=⌊kdb⌋.

载荷的记号。 H=⌊db/k⌋ 由 d,b,k 算出，不是输入。本模型采用分片专家模型：一个
slot 的 db 字节激活分摊到它选中的 k 个专家上，每个专家只收到自己那 H 字节，算出
一个部分结果，汇集步骤再把各部分合起来。因此无论 k 是多少，一个 slot 在网络上总
共只传约 db 字节（向下取整可能让激活里有几个字节用不上）；更常见的做法是把整份
激活交给每个被选中的专家，那样网络上的字节数要乘 k。各 MoE 层的隐层宽度与元素类
型相同，单 slot 的字节数不随层变化，逐层变化的是负载 Tℓ。

一个 EP 组占据哪些物理卡由 3.1 节的嵌入确定，只取决于 P 与 D，因此对每个 EP 组
、每一层都一样。记一个 rank 在该集合内的节点内对端数 pin 和跨节点对端数 pout=
P−1−pin（由嵌入直接算出，参赛者无法选择）。该层一次 AllToAll 的时长按最慢的那
类对端算：

xℓ=max(⌈BinpinXℓ⌉, ⌈BoutpoutXℓ⌉)⋅Fio.

流量按实际对端数分项，不随 P 线性外推。

流量与 slot 在专家上如何分布无关：无论 aℓ,e 取多少，穿过 EP 组边界的总流量都是
 TℓH(P−1)/P，因为 rank r 的发出量为 (H/P)(Tℓ−Ar)，其中 Ar 是落在 r 上那些专
家的 slot 数，而 ∑rAr=Tℓ；Bin 与 Bout 是两类对端的聚合带宽，为该类所有对端
共享。所以偏斜只影响计算一侧（通过 mℓ），不影响通信一侧。这样建模的理由很实际
：跨节点带宽通常比节点内低一个数量级，把 P 调大能摊薄每卡计算量，却会把越来越多
流量推上窄带，两者必须显式权衡（见 7.3 节）。

4.5 一步训练时间

给定 (μ,V,P,D)、PSI 行声明的块数 K、ψ、σ 与调度，评测器：

 1. 按 4.1、4.3、4.4 算出每个操作被引用时的时长；
 2. 按 4.2 检查依赖与资源，模拟得到每个操作的实际起止；
 3. 一步训练时间取所有操作完成时刻的最大值：

Time=所有操作max(t+时长).

评测器只做前向模拟，不做任何优化或搜索：调度由参赛者给出，评测器只负责判分。也
正因如此，参赛者可以放心使用任何启发式，哪怕搜索并不完整：评测器不需要知道最优
值是多少。

4.6 每卡内存

物理卡 q=v⋅(P⋅D)+d⋅P+p（见 3.1 节）属于卡组 v，该卡组拥有映射到它的每一块中的层
：一般是块 v，K=2V 时还要加上块 2V−1−v。同一卡组的每张卡持有相同的层，下面的核
算因此对一个卡组的全部 P⋅D 张卡都适用。三块占用：

Mexp(q)Movl(q)Mact(q)=ℓ∈卡 q∑(PEZ+Zs),=U⋅tmax #{时刻 t 上已开始未完成的
通信操作},=Uact⋅tmax #{时刻 t 上前向已完成、反向未完成的 (mb,ℓ)}.

三块的直觉分别是：

  • Mexp 是静态的：放几个专家就吃几份参数，且按层数线性累加。这是「切层」与「
    网格」直接影响的内存。
  • Movl 是通信缓冲：一个卡组只有一套网络引擎（4.2 第 3 条），因此不会有两次通
    信同时进行，计费的是同时在用的缓冲数峰值。一次传输恰好在下次开始时结束，要
    算作两块，因为前一块已经释放、后一块正在填充；反过来，留出空隙的调度是用一
    单位时间换一块内存。
  • Mact 是激活值，也随调度变：前向铺得越开、反向压得越后，同时活着的激活就越
    多。一个激活 (mb,ℓ) 从它前向结束那一刻起（即该 (mb,ℓ) 的 comb 结束）到它反
    向开始（即它的 s_bwd 开始）为止，算作存活；前向恰好在反向开始时结束，该时刻
    仍持有这份激活。

Movl 里的通信操作指 disp、comb、comb_bwd、disp_bwd 四种。必须对每张卡满足 Mexp
+Movl+Mact≤M，否则该映射非法，得 0 分。

4.7 合法性约束

 1. V⋅P⋅D=R，V,P,D≥1，P∣E，且 P∣S 或 S∣P；
 2. PSI 行先声明块数 K，随后恰好是 K−1 个切点，严格递增且覆盖 0..L，且 K=V 或 K
    =2V；
 3. MAP 每行合法：σℓ,e∈[0,P)，每个取值恰好出现 E/P 次；
 4. 调度满足 4.2 的五条规则，且只引用 4.1 表中的操作名；
 5. nmb 为偶数（输入保证）。

5. 评测方式

 1. 求解器为每个测试点输出完整映射。测试点保证存在合法映射，所以不必输出无解标
    记。
 2. 映射非法、越界或解析出错的，该测试点记 0 分。
 3. 合法输出由评测器按第 4 节模拟，得到 Time，Time 越小得分越高；各测试点按相对
    成绩聚合排名。成绩并列时，先比求解器的 CPU 时间，再比提交时间。
 4. 每个测试点的运行时限为 10 秒（墙钟时间，评测器自身的模拟耗时不计入）；超时
    的测试点记 0 分。

本题不要求精确最优解，鼓励在时间预算内探索不同的映射与调度策略：评测器只做模拟
判分，搜索的深度与广度由选手自己取舍。
