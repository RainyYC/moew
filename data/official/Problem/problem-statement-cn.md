# 满足内存约束的 MoE 分块与重叠吞吐优化

## 1. 背景

在大模型训练中，MoE（Mixture of Experts）层把「一份大 FFN」换成 $E$ 个小专家：每个 token 只被路由到少数几个专家，由这些专家所在的 NPU 完成计算。这样可以在算力基本不变的前提下把参数量放大一个数量级；代价是**数据要流动**：token 必须先被送到专家所在的卡上，算完再送回来。

为了让集群跑得快，系统通常同时使用两种并行方式：

- **专家并行（Expert Parallelism, EP）**：把同一层的 $E$ 个专家分到不同的 NPU 上。token 通过 AllToAll 被送到目标专家所在的卡，算完再 AllToAll 回来。
- **管线并行（Pipeline Parallelism, PP）**：把 $L$ 层切成若干段（stage），microbatch 像流水线一样依次流过各段。DualPipe 等方案会让 microbatch 从两端同时注入，以减少空泡。

这两件事互相纠缠：EP 决定 AllToAll 走节点内还是跨节点（两者带宽往往差一个数量级），PP 决定哪些层在同一张卡上、以及流水线的空泡有多少；而每张卡的 HBM（高带宽内存）是硬上限，专家参数、通信缓冲、激活值都抢同一块内存。

**本题：** 给定集群拓扑、每卡内存、模型规模与逐层负载，输出一份完整映射（网格、切层、逐层专家放置、整步调度），使一步训练的 wall-clock time 最小，且每张卡均不超过内存上限。

### 问题难点

三层决策耦合在一起：

- **网格** $(V,P)$：stage 数与专家并行规模。它决定每卡驻留几个专家（每层 $E/P$ 个），专家参数占多少内存由此而来；通信对端分布在几个节点上也由它决定，因而决定了流量走节点内还是跨节点。
- **切层** $\psi$：$L$ 层怎么连续切成 $V$ 段。它决定哪些层共卡，因而决定每张卡的内存预算，也决定最慢的 stage 有多慢。
- **调度**：通信与计算在时间轴上如何交错。它决定全部重叠与空泡，也决定某一时刻还有多少缓冲与激活没有释放。

总运行时间取决于几个互相牵制的瓶颈：最挤的通信边、最慢的 stage、最长的依赖操作链。内存上限又进一步限制哪些配置可行。四项决策（网格、切层、专家放置与调度）因此同时作用于时间与内存，必须一起定下来，不能一项接一项地先后求解。

### 商业价值

MoE 是主流大模型的核心结构，EP/PP 联合映射直接决定训练吞吐与显存占用。自动化的映射与调度搜索可降低大模型训练对专家调参的依赖，为 AI 编译器与集群调度栈提供可复用的布局与调度能力。

### 1.1 一次前向的四个步骤，与重叠从何而来

一个 MoE 层在每张卡上的前向过程包含四个步骤：

1. **共享专家**：所有 token 都经过它。纯计算，不涉及跨卡通信。
2. **分发 AllToAll**：把本地 token 按路由结果发给目标专家所在的卡。纯通信。
3. **GroupGEMM**：计算落在本卡的专家。纯计算。
4. **汇集 AllToAll**：把专家的输出送回 token 原来的卡。纯通信。

反向对应地产生六个步骤：共享专家的输入梯度与权重梯度、专家输入梯度与专家权重梯度，以及分发与汇集各自的反向通信。

**前向与反向合起来，每张卡上的每一层共十个步骤。** 关键点在于：每个 NPU 的通信能力与计算能力都是固定的，通信走通信引擎，计算走计算引擎，两者可以同时进行。第 4.1 节给出每个步骤占用的引擎与时长，第 4.2 节给出它们之间的依赖；运行时间上的收益，正来自在满足这些依赖的前提下设计重叠。一层的十个步骤并非一条链。前向里共享专家 `s` 与分发并排；反向正好镜像：路由链为 `comb_bwd → gemm_dx → disp_bwd`，共享专家的输入梯度 `s_bwd` 与 `comb_bwd` 同时释放，只须赶在 `disp_bwd` 之前完成；两个权重梯度步骤则只要排在 `comb_bwd` 之后即可。于是除了跨 microbatch、跨层交错，还能把 `s_bwd` 压到反向汇集底下，或把一层的权重梯度塞进另一层的空档，再挤出一些重叠。

**已有文献中出现过三种经典排法。** 它们都能用本题的输出格式表达，但我们允许更一般的调度：参赛者提交的是一份完整调度，三种排法只是它的特例。

- **1F1B**（一次前向、一次反向）：流水线填满之后，每个 stage 在新 microbatch 的前向与较旧 microbatch 的反向之间来回切换，前向与反向两侧都保持忙碌，同时在飞的 microbatch 数保持有界。见 PipeDream [3]。
- **ZB1P**（把反向拆开、把其中较轻的一半滑出去）：第 4.2 节第 1 条把反向拆成两半。一半是输入梯度，走路由链 `comb_bwd → gemm_dx → disp_bwd`：共享专家的输入梯度 `s_bwd` 与 `comb_bwd` 同时释放，只须赶在 `disp_bwd` 之前完成。另一半是两个权重梯度步骤 `gemm_dw` 与 `s_dw`，它们只等送进来的梯度。路由链首尾相接，权重梯度却可以落在 `comb_bwd` 之后的任何时刻，于是能填进计算引擎原本空闲的缝里。第 2 条又把相邻层的反向锚在 `disp_bwd`，也就是路由链的末端；这种推迟因此是结构性的，而不只是“允许”——把权重梯度往后挪，不会拖慢任何别的层。见零气泡流水线工作中的 ZB-H1 排法 [2]。
- **DUALPIPE**（一张卡上放两块）：$K=2V$ 时一个卡组持有块 $k$ 及其镜像 $2V-1-k$，一块于是可以跑前向，另一块同时跑另一个 microbatch 的反向；$K=V$ 时一张卡只持有一块，这种排法无从谈起。见 DeepSeek-V3 报告中的 DualPipe 排法 [1]。

**为了让题目可控，我们做了若干简化。** 操作是原子的：不允许 tile 级切块，因此第 4.1 节的任何操作都不会被拆成几部分（见 3.2 节）。AllToAll 与 GroupGEMM 也不会融合进同一个 kernel（与 UniEP [4] 不同），因为融合意味着载荷还没到齐就得消费它（第 4.2 节第 1 条）。真正能在**同一个 microbatch 内**与分发重叠的只有共享专家：它读本层进来的激活、结果并入本层的 `comb`，所以能和同层正在等待的 AllToAll 并排跑——这正是 4.2 节第 1 条所围绕的重叠，也是 DualPipe 藏起来的那一手。负载分布固定且已知：$a_{\ell,e}$ 在整步中不变，一份调度在开始前就声明所有开始时刻，而不是在运行时自适应。最后，计算与通信互不拖慢：每个操作的时长恰好如第 4.1 节所述。

## 2. 输入

所有量均为非负整数，同一行以空白分隔。

本题不模拟真实时钟：**所有时间量都以同一个抽象「时间单位」计**，`Time` 的绝对数值没有物理含义，只用于排名比较。带宽 $B_{\mathrm{in}},B_{\mathrm{out}}$ 的单位是字节/时间单位，时间系数 $F_{\mathrm{s}},F_{\mathrm{io}},F_{\mathrm{in}}$ 的单位是时间单位。

**第 1 行** $N\ S\ M\ B_{\mathrm{in}}\ B_{\mathrm{out}}$：集群与内存。

| 符号 | 含义 |
|------|------|
| $N$ | 节点数 |
| $S$ | 每节点 NPU 数；总卡数 $R=N\cdot S$ |
| $M$ | 每卡 HBM 上限（字节） |
| $B_{\mathrm{in}}$ | 节点内带宽（字节/时间单位）。同节点通信都走它，通常远大于跨节点带宽 |
| $B_{\mathrm{out}}$ | 节点间带宽（字节/时间单位），$B_{\mathrm{out}}\le B_{\mathrm{in}}$ |

**第 2 行** $L\ E\ Z\ Z_{\mathrm{s}}\ U\ U_{\mathrm{act}}\ k\ n_{\mathrm{mb}}\ F_{\mathrm{s}}\ F_{\mathrm{io}}\ F_{\mathrm{in}}\ \alpha_{\times}\ \beta_{\times}$：模型规模、缓冲与时间系数。

| 符号 | 含义 |
|------|------|
| $L$ | MoE 层数 |
| $E$ | 每层可路由专家数（逐层相同） |
| $Z$ | 单个可路由专家参数大小（字节）。每卡每层驻留 $E/P$ 个专家，故每层占用 $(E/P)Z$ 字节 |
| $Z_{\mathrm{s}}$ | 共享专家大小（每卡每层一份，可为 0） |
| $U$ | 一块通信缓冲的字节数。每个卡组只有一套通信引擎（4.2 第 3 条），同一时刻每张卡最多有一个通信操作在途，占用 $U$ 字节；见 4.6 |
| $U_{\mathrm{act}}$ | 一个 (microbatch, 层) 的激活值字节数；见 4.6 |
| $k$ | 每个 token 路由到的专家数（top-$k$，逐层相同） |
| $n_{\mathrm{mb}}$ | microbatch 数（偶数）。它决定流水线里同时推进多少个 microbatch |
| $F_{\mathrm{s}}$ | 共享专家时间系数（每 slot）：共享专家处理一个 slot 需要多少时间单位 |
| $F_{\mathrm{io}}$ | AllToAll 通信系数（每单位带宽时间的时间单位，见 4.4） |
| $F_{\mathrm{in}}$ | GroupGEMM 计算系数（每 slot 占用多少时间单位，见 4.3） |
| $\alpha_{\times},\beta_{\times}$ | 反向系数（微单位）：$\alpha=10^{-6}\alpha_{\times}$，$\beta=10^{-6}\beta_{\times}$。这两个系数决定前向、反向以及反向中权重梯度部分的相对耗时；具体乘在哪一步见第 4.1 节 |

**第 3 行** $d\ b$：隐层宽度（元素数）与元素字节数。每个 token 的激活为 $d\cdot b$ 字节，分摊到它路由的 $k$ 个专家上，因此每 slot 发往一个对端的载荷是 $H=\lfloor d\,b/k\rfloor$ 字节。

**第 4 行起共 $L$ 行**，每行描述一层的负载。第 $\ell$ 行为 $T_\ell$ 与可选负载向量：

- $T_\ell$ 是层 $\ell$ 的 token-slot 数（top-$k$ 已展开，即 $T_\ell=k\cdot B_\ell$，其中 $B_\ell$ 是该层 token 数）。
- 若该层负载均衡，该行只写 $T_\ell$。
- 否则在其后写 $E$ 个整数 $a_{\ell,0}\dots a_{\ell,E-1}$，表示路由到各专家的 slot 数，满足 $\sum_e a_{\ell,e}=T_\ell$。

同一实例的 $L$ 层还须满足：每个 $T_\ell$ 都是 $k$ 的倍数，且 $\max_\ell T_\ell/\min_\ell T_\ell\le1.2$；这两条与其余数据范围一并列在第 6 节。

注意，输入给出的**负载分布是静态的**：每层每个专家分到多少 slot 在输入里已经确定，不随训练步变化。建模时也不假定它均匀：真实训练中门控输出天然偏斜，各层的偏斜程度还各不相同。负载既已知，专家怎么放（见 4.3 节）就成了一个可以据此优化的决策。

## 3. 输出

按以下格式输出完整映射：

```text
V P
PSI
K ψ_1 ψ_2 ... ψ_{K-1}
MAP
σ_0,0 σ_0,1 ... σ_0,E-1
...
SCHEDULE
t mb:ℓ:op mb:ℓ:op ...
...
```

### 3.1 逐字段说明

| 字段 | 含义 |
|------|------|
| `V` | 管线 stage 数（沿层切分） |
| `P` | 专家并行规模（同一层专家切到几个 rank）。须满足 $P\mid S$ 或 $S\mid P$，以保证 EP 组与节点对齐（见 4.4 节） |
| `PSI` | 块数 $K$，紧跟在同一行后面的是 $K-1$ 个切点 $\psi_1,\dots,\psi_{K-1}$，严格递增。$K$ 只能取 $V$（每个卡组一块，默认）或 $2V$（每个卡组两块），其他取值一律非法；$K=1$ 时该行只写块数 `1`，不带切点。块 $k$ 含层 $[\psi_k,\psi_{k+1})$；块 $k$ 属于卡组 $g(k)=k$（$k<V$）或卡组 $g(k)=2V-1-k$（$k\ge V$），即镜像配对。因此 $K=2V$ 时，每个卡组各持一块靠前的块和一块靠后的块 |
| `MAP` | 逐层专家放置，共 $L$ 行。第 $\ell$ 行是 $E$ 个整数 $\sigma_{\ell,e}\in[0,P)$：专家 $e$ 放在本 EP 组的第几个 rank。每个取值恰好出现 $E/P$ 次 |
| `SCHEDULE` | 整步调度，见下 |

**网格与物理卡。** $V$、$P$ 由参赛者选择，两者一起决定流水线有多少个 stage、一个 EP 组有多宽。参赛者选择不了的是 $V\times P$ 这块网格如何嵌入物理卡：给定这两个数，评测器按固定规则 $q=v\cdot P+p$ 嵌入（$p$ 最快变）。哪连续 $P$ 张卡构成一个 EP 组、每个 stage 的卡块落在哪里，都由这条规则决定，因此物理卡 $q$ 就是网格坐标 $(v,p)$ 对应的那张卡：一个 EP 组的 $P$ 个 rank 是连续的卡，每个 stage 占一段连续的 $P$ 张卡。网格必须装得进集群：$V\cdot P\le R$。若 $V\cdot P<R$，则只有按上述顺序的前 $V\cdot P$ 张卡承载层，其余 $R-V\cdot P$ 张卡空闲——不执行操作，也不计内存。又因为 $P\mid S$ 或 $S\mid P$，一个 EP 组要么完全落在节点内，要么整齐地跨节点，4.4 节的节点内对端数因此是确定的。共用同一个 stage 的那 $P$ 张卡称为一个**卡组**：它拥有该 stage 的层，也是计算引擎占用与内存的核算单位（见 4.2 与 4.6 节）。

### 3.2 调度格式

调度是一张时间表。**每一行是一个时刻**，行首是整数时刻 $t$，其后是若干个操作，写作 `mb:ℓ:op`：

- `mb` 是 microbatch 编号，范围 $[0,n_{\mathrm{mb}})$；
- `ℓ` 是层号，范围 $[0,L)$，它属于哪一块由 `PSI` 行声明的块数 $K$ 与切点决定，而 stage 就是拥有该块的卡组，因此条目里不必再写 stage；
- `op` 是操作名，取自 4.1 节的十种。

**同一行内的所有操作在同一时刻开始并发执行。** 每层恰好有第 4.1 节的十个操作，每个 microbatch 各一次；十个之外的操作名一律非法。

调度写的是每个卡组一张**代表卡**的动作，因此一份调度里共 $V$ 张代表卡。一个卡组里的 $P$ 张卡在调度意义下等价：各自负责自己的专家分片和自己的数据，组内其余每张卡都跟随同一份调度。条目给出开始时刻和三元组 $mb{:}\ell{:}op$：在该时刻，拥有层 $\ell$ 的卡组在其全部卡上为 microbatch $mb$ 同时执行该层的操作 $op$。每个 (microbatch, 层, 操作) 三元组在清单里恰好出现一次。

一个条目由哪个卡组执行，取决于层号和 `PSI` 行：行里的切点把 $L$ 层切成 $K$ 块。$K=V$ 时每个卡组持有一段连续的层，卡组 $k$ 就持块 $k$；这一段同时服务其中各层的前向与反向，一个 microbatch 的前向会依次访问每个卡组。$K=2V$ 时块到卡组按镜像配对：块 $k$ 属于卡组 $k$（$k<V$），或属于卡组 $2V-1-k$（$k\ge V$）。于是每个卡组拥有模型的两块，一块来自层区间前半、一块来自后半，两块的参数都驻留在它的卡上；这两块一块靠近层序开头，一块靠近末尾。前向从开头走向末尾，反向则相反，因此稳态调度可以用年轻 microbatch 的前向占据靠前的那块，用较旧 microbatch 的反向占据靠后的那块，让该卡组的两套引擎同时为两个不同的 microbatch 工作。这正是 `DUALPIPE` 一类调度利用的性质。此时流水线有 $2V$ 块深，一个 microbatch 的前向会访问每个卡组两次。

**对输出的约束**：

1. $t$ 必须非降，调度按时间顺序书写。
2. 同一行内不得出现两个占用同一引擎的操作（具体规则见 4.2）。
3. 行与行之间不必等距：某一行写完，直接写下一个有新操作的时刻即可。

一个最小的完整例子（7.1 节的第一条 microbatch）：

```text
1 2
PSI
1
MAP
0 1
SCHEDULE
0 0:0:disp 0:0:s
70 0:0:gemm
94 0:0:comb
```

**说明**：时刻 0，分发（时长 70）与共享专家（时长 16）同时开始：二者都是本层的入口操作——分发没有前驱，共享专家只依赖本层进来的激活——共享专家因此藏在分发底下。时刻 70 开始 GroupGEMM（24），时刻 94 开始汇集（70）；汇集既要等 GroupGEMM，也要等共享专家，而后者早已完成。最后一次操作在 $94+70=164$ 结束，故 $\mathrm{Time}=164$。

## 4. 得分计算（模拟过程）

### 4.1 十种基本操作

每个操作占用两套引擎中的一套，时长取下表中的一个表达式。表达式由每层的三个量 $m_\ell$、$x_\ell$、$s_\ell$（定义见 4.3 与 4.4 节）和几个全局系数算出。

| 操作 | 引擎 | 时长 | 含义 |
|------|------|------|------|
| `s` | 计算 | $s_\ell$ | 共享专家前向 |
| `disp` | 通信 | $x_\ell$ | 分发 AllToAll |
| `gemm` | 计算 | $m_\ell F_{\mathrm{in}}$ | 落在本卡的专家前向 |
| `comb` | 通信 | $x_\ell$ | 汇集 AllToAll |
| `s_bwd` | 计算 | $\alpha\,s_\ell$ | 共享专家输入梯度 |
| `comb_bwd` | 通信 | $\alpha\,x_\ell$ | 汇集反向 |
| `gemm_dx` | 计算 | $\alpha\,m_\ell F_{\mathrm{in}}$ | 专家输入梯度 |
| `gemm_dw` | 计算 | $\alpha\beta\,m_\ell F_{\mathrm{in}}$ | 专家权重梯度 |
| `disp_bwd` | 通信 | $\alpha\,x_\ell$ | 分发反向 |
| `s_dw` | 计算 | $\alpha\beta\,s_\ell$ | 共享专家权重梯度 |

所有时长向上取整为整数。前向拆成四个步骤、反向拆成六个步骤，是为了让通信与计算能以单个步骤为粒度重叠。系数决定这些步骤的相对长度：反向的四个输入梯度步骤是各自前向步骤的 $\alpha$ 倍，两个权重梯度步骤再乘一层 $\beta$，因此一次反向约等于 $\alpha(1+\beta)$ 次前向，其中权重梯度占 $\beta/(1+\beta)$。

### 4.2 依赖与资源

合法调度必须满足：

1. **层内依赖**：路由专家链固定为：前向
   `disp → gemm → comb`，反向 `comb_bwd → gemm_dx → disp_bwd`，每一步都排在前一步之后。共享专家不在这两条链上——`s` 只依赖本层输入（与释放 `disp` 的是同一条边，见第 2 条），且须在 `comb` 之前收尾；`s_bwd` 只依赖送进来的梯度（与释放 `comb_bwd` 的是同一条边；最后一层则看本层自己的 `comb`），且须在 `disp_bwd` 之前收尾，因为 `disp_bwd` 要加的梯度里有共享专家那一份。两个**权重梯度步骤** `gemm_dw` 与 `s_dw` 只等 `comb_bwd`，之后放在该层反向的哪里都行。两个第一个反向步骤 `s_bwd` 与 `comb_bwd` 都不得早于本层自己的 `comb` 结束。
2. **管线依赖（层序）**：同一个 microbatch 内，激活逐层向前流动，梯度沿同样的路径反向流回。层 $\ell$ 的两个第一个前向操作（`s` 与 `disp`）要等层 $\ell-1$ 的前向完成，即在它的 `comb` 之后，对每个 $\ell\ge1$ 成立；层 $\ell$ 的两个第一个反向操作（`s_bwd` 与 `comb_bwd`）要等层 $\ell+1$ 的反向送出输入梯度，即在它的 `disp_bwd` 之后，对每个 $\ell\le L-2$ 成立；这还要叠加第 1 条里它们对本层 `comb` 的依赖。锚点取 `disp_bwd`，而不是层 $\ell+1$ 反向的最后一步，因为层 $\ell$ 只消费梯度：层 $\ell+1$ 在 `disp_bwd` 之后做的都是它自己的权重梯度，下游没有东西读它，也就拖不住层 $\ell$。两条陈述都建立在层上而不是块上：它们同样约束共用一个卡组的两层，因此不必在它们之上再加块一级的陈述。
3. **资源互斥**：一个卡组有一套计算引擎和一套通信引擎（见 3.1 节）。任一时刻它最多运行一个计算类操作和一个通信类操作；$K=2V$ 时这条限制同时覆盖它的两块，两块的操作因此争用同一对引擎。
4. **因果性**：条目声明的 $t$ 不得早于其依赖的完成时刻；违反则该映射非法。

这四条规则就是全部的调度约束：参赛者不限于 1.1 节介绍的经典排法，任何满足 4.2 的调度都可以提交。

### 4.3 负载、放置与计算时间

每层每 rank 放 $E/P$ 个专家（放哪几个由 `MAP` 决定）。记 rank $r$ 在本层承载的 slot 数

$$
L_{\ell,r}=\sum_{e:\ \sigma_{\ell,e}=r}a_{\ell,e},
\qquad
m_\ell=\max_r L_{\ell,r}.
$$

计算类操作的时长取决于该层所在 EP 组内**最慢的那个 rank**，所以取 $m_\ell$ 而不是平均值：某个 rank 上的专家越热，整层就得等它。

若某层的输入行不带负载向量，评测器先把它 $T_\ell$ 个 slot 尽量均匀地分给 $E$ 个专家，再算 $m_\ell$，于是各专家分到的 slot 数至多相差 1。负载均衡时 $m_\ell=\lceil T_\ell/P\rceil$，与常规公式一致。负载偏斜时 $m_\ell$ 还取决于 `MAP`：把热点专家分散到不同 rank，就能压低 $m_\ell$。注意通信量 $X_\ell$ 只依赖总量 $T_\ell$（见 4.4），所以**偏斜只抬高计算、不改变通信**，两类引擎对偏斜的敏感程度并不相同。

### 4.4 通信时间

每 rank 每层发往本 EP 组内其余 $P-1$ 个 rank 中**每一个**的字节数为：

$$
X_\ell=\left\lceil \frac{T_\ell\,H}{P}\right\rceil,
\qquad H=\left\lfloor \frac{d\,b}{k}\right\rfloor .
$$

一个 rank 持有 $T_\ell/P$ 个 slot，其中专家在本 rank 上的那 $1/P$ 留给自己，其余 $(P-1)/P$ 要发给别的 rank，合计约 $T_\ell H(P-1)/P$ 字节；平摊到 $P-1$ 个对端，每个对端就是 $X_\ell$。发往节点内对端共 $p_{\mathrm{in}}X_\ell$ 字节，发往跨节点对端共 $p_{\mathrm{out}}X_\ell$ 字节：两路同时进行、各走自己的带宽，所以一次 AllToAll 的时长取较慢的那一路。

**载荷的记号。** $H=\lfloor d\,b/k\rfloor$ 由 $d,b,k$ 算出，不是输入。本模型采用**分片专家模型**：一个 **token** 的 $d\,b$ 字节激活分摊到它路由到的 $k$ 个专家上，也就是分摊到它的 $k$ 个 slot 上，每个 slot 只把自己那 $H$ 字节送给对应的专家，由该专家算出一个部分结果，汇集步骤再把各部分合起来。因此无论 $k$ 是多少，一个 **token** 在网络上总共只传约 $d\,b$ 字节（向下取整可能让激活里有几个字节用不上）。计算量按 slot 计、与每个 slot 带多少字节无关，所以这一分摊只改变发送的字节数；$H$ 对各 MoE 层相同，逐层变化的只有 $T_\ell$。

一个 EP 组占据哪些物理卡由 3.1 节的嵌入确定，只取决于 $P$，因此对每个 EP 组、每一层都一样。记一个 rank 在该集合内的**节点内对端数** $p_{\mathrm{in}}$ 和**跨节点对端数** $p_{\mathrm{out}}=P-1-p_{\mathrm{in}}$（由嵌入直接算出，参赛者无法选择）。该层一次 AllToAll 的时长按最慢的那类对端算：

$$
x_\ell=\max\!\left(\left\lceil\frac{p_{\mathrm{in}}X_\ell}{B_{\mathrm{in}}}\right\rceil,\
\left\lceil\frac{p_{\mathrm{out}}X_\ell}{B_{\mathrm{out}}}\right\rceil\right)\cdot F_{\mathrm{io}} .
$$

流量按**实际对端数**分项，不随 $P$ 线性外推。

流量与 slot 如何分布在专家上无关：无论 $a_{\ell,e}$ 取多少，每个 rank 发出的总量都一样，所以偏斜只影响计算（通过 $m_\ell$）。$B_{\mathrm{in}}$ 与 $B_{\mathrm{out}}$ 是两类对端的聚合带宽，由该类对端共享。这样建模的理由很实际：跨节点带宽通常比节点内低一个数量级，把 $P$ 调大能摊薄每卡计算量，却会把越来越多流量推上窄带，两者必须显式权衡（见 7.3 节）。

### 4.5 一步训练时间

给定 $(\mu,V,P)$、`PSI` 行声明的块数 $K$、$\psi$、$\sigma$ 与调度，评测器：

1. 按 4.1、4.3、4.4 算出每个操作被引用时的时长；
2. 按 4.2 检查依赖与资源，模拟得到每个操作的实际起止；
3. 一步训练时间取所有操作完成时刻的最大值：

$$
\mathrm{Time}=\max_{\text{所有操作}}\bigl(t+\text{时长}\bigr).
$$

评测器只做前向模拟，**不做任何优化或搜索**：调度由参赛者给出，评测器只负责判分。也正因如此，参赛者可以放心使用任何启发式，哪怕搜索并不完整：评测器不需要知道最优值是多少。

### 4.6 每卡内存

物理卡 $q=v\cdot P+p$（见 3.1 节）属于卡组 $v$，该卡组拥有映射到它的每一块中的层：一般是块 $v$，$K=2V$ 时还要加上块 $2V-1-v$。同一卡组的每张卡持有相同的层，下面的核算因此对一个卡组的全部 $P$ 张卡都适用。三块占用：

$$
\begin{aligned}
M_{\mathrm{exp}}(q)
&=\sum_{\ell\in\text{卡 }q}\left(\frac{E}{P}Z+Z_{\mathrm{s}}\right),\\[2mm]
M_{\mathrm{ovl}}(q)
&=U\cdot\max_{t}\ \#\{\text{时刻 }t\text{ 上已开始未完成的通信操作}\},\\[2mm]
M_{\mathrm{act}}(q)
&=U_{\mathrm{act}}\cdot
\max_{t}\ \#\{\text{时刻 }t\text{ 上前向已完成、反向未完成的 }(mb,\ell)\}.
\end{aligned}
$$

三块的直觉分别是：

- $M_{\mathrm{exp}}$ 是静态的：放几个专家就吃几份参数，且按层数线性累加。这是「切层」与「网格」直接影响的内存。
- $M_{\mathrm{ovl}}$ 是通信缓冲：一个卡组只有一套网络引擎（4.2 第 3 条），因此不会有两次通信同时进行，计费的是同时在用的缓冲数峰值。一个通信操作恰好在下一个启动时结束，要算作两块，因为前一块已经释放、后一块正在填充；反过来，留出空隙的调度是用一单位时间换一块内存。
- $M_{\mathrm{act}}$ 是激活值，也随调度变：前向铺得越开、反向压得越后，同时活着的激活就越多。一个激活 $(mb,\ell)$ 从它前向结束那一刻起（即该 $(mb,\ell)$ 的 `comb` 结束）到它反向开始（即它的 `s_bwd` 开始）为止，算作**存活**；前向恰好在反向开始时结束，该时刻仍持有这份激活。

$M_{\mathrm{ovl}}$ 里的通信操作指 `disp`、`comb`、`comb_bwd`、`disp_bwd` 四种。必须对网格内的每张卡满足 $M_{\mathrm{exp}}+M_{\mathrm{ovl}}+M_{\mathrm{act}}\le M$，否则该映射非法，得 0 分。

### 4.7 合法性约束

1. $V\cdot P\le R$，$V,P\ge 1$，$P\mid E$，且 $P\mid S$ 或 $S\mid P$；
2. `PSI` 行先声明块数 $K$，随后恰好是 $K-1$ 个切点，严格递增且覆盖 $0..L$，且 $K=V$ 或 $K=2V$；
3. `MAP` 每行合法：$\sigma_{\ell,e}\in[0,P)$，每个取值恰好出现 $E/P$ 次；
4. 调度满足 4.2 的四条规则，且只引用 4.1 表中的操作名；
5. $n_{\mathrm{mb}}$ 为偶数（输入保证）。

## 5. 评测方式

1. 求解器为每个测试点输出完整映射。测试点保证存在合法映射，所以不必输出无解标记。
2. 映射非法、越界或解析出错的，该测试点记 $0$ 分。
3. 合法输出由评测器按第 4 节模拟，得到 $\mathrm{Time}$，**$\mathrm{Time}$ 越小得分越高**；各测试点按相对成绩聚合排名。成绩并列时，先比求解器的 CPU 时间，再比提交时间。
4. 每个测试点的运行时限为 $10$ 秒（墙钟时间，评测器自身的模拟耗时不计入）；超时的测试点记 $0$ 分。

本题不要求精确最优解，鼓励在时间预算内探索不同的映射与调度策略：评测器只做模拟判分，搜索的深度与广度由选手自己取舍。

## 6. 数据范围

- **集群**：$N\le 32$，$S\le 16$（$R=NS\le 512$）。
- **模型**：$3\le E\le 512$，$L\le 64$，$k\le 64$，$n_{\mathrm{mb}}\le 10^3$ 且为偶数，$T_\ell\le 10^9$，$d\le 2^{16}$，$b\in\{1,2,4\}$。
- **每层负载**：输入保证每个 $T_\ell$ 都是 $k$ 的倍数，且同一实例的 $L$ 层满足 $\max_\ell T_\ell/\min_\ell T_\ell\le1.2$。前者使 $B_\ell=T_\ell/k$ 为整数，后者使最重的一层至多比最轻的一层重 $20\%$。
- **网格与切分**：$V\le 64$（切点规则本身已蕴含 $V\le L$），$V\cdot P\le R$，$P\mid E$，且 $P\mid S$ 或 $S\mid P$。
- **时间系数**：$F_{\mathrm{s}},F_{\mathrm{io}},F_{\mathrm{in}}\le 10^6$，$\alpha_\times,\beta_\times\le 2\times10^6$。
- **内存与缓冲**：$Z,Z_{\mathrm{s}}\le 10^9$；$1\le U,U_{\mathrm{act}}\le 2^{20}$（1 MiB）；$M\le 10^{18}$，且不小于最小驻留量 $\min_{(V,P)}\left[(L/V)(E/P)Z+(L/V)Z_{\mathrm{s}}\right]$。
- **带宽**：$1\le B_{\mathrm{out}}\le B_{\mathrm{in}}\le 2\times10^5$；$B_{\mathrm{in}}$ 与 $B_{\mathrm{out}}$ 同量级时，节点内带宽才会影响得分。

调度条目数不超过 $2\times10^7$。乘积请使用 128 位中间量。

## 7. 样例

下面六个样例都给出输入与输出，用来对照格式；说明里的数值都能按第 4 节的公式手算复核，各输出也都满足第 4.7 节的合法性约束。

**这些输出是可行解，不是最优解**，只用来交代格式与机制：清单里的数值都取自第 4 节的公式，排法本身则没有优化过，每个 `SCHEDULE` 都还有压缩空间（更细的切分、更紧的交错、更好的 `MAP`）。样例的规模压到了可以手算，真实规模下能拉开差距的那些优化，在这里往往施展不开。样例也不代表测试点的规模与难度：测试点按第 6 节的范围生成，$L$ 与 $E$ 都可以远大于这里，而样例不必落在第 6 节的取值范围内（例如 7.1、7.5、7.6 的 $E=2$）。
### 7.1 样例 1（共享专家藏在分发底下；两条 microbatch 在双引擎上交错）

**输入**

```text

1 2 20 0 1 1 1 2 2 10 6 1000000 1000000
8 2

```

$R=2$，同节点。$H=\lfloor8\cdot2/1\rfloor=16$，$X=\lceil8\cdot16/2\rceil=64$，$p_{\mathrm{in}}=1$，$p_{\mathrm{out}}=0$，$x=\lceil64/10\rceil\cdot10=70$。$P=2$ 时每 rank 一个专家，$m_0=\lceil8/2\rceil=4$，故 `gemm`$=4\cdot6=24$；`s`$=8\cdot2=16$。整个模型只有这一层，又落在唯一卡组的唯一一块里，因此根本没有层边。

**内存把 $P$ 顶起来了**：$M=39$，而 $P=1$ 时每张卡要独吞 2 个专家（$2\times20=40$ 字节参数），已经超了，所以 $P\ge2$；$P=2$ 时每卡只放 1 个专家，故 $M_{\mathrm{exp}}=20$ 字节参数，再加 $M_{\mathrm{ovl}}=1$ 块缓冲与 $M_{\mathrm{act}}=1$ 份激活，共 22 $\le39$，可行。

$R=4$，两节点。共 $L=2$ 层，每层 $T_\ell=12$ 个 slot。

两层时 $V\le L=2$。取满宽 $V\cdot P=R=4$，只剩 $P=2$（$V=2$）与 $P=4$（$V=1$）两种；更窄的网格也救不了：$P=1$ 要 $V=4$ 个 stage，且一张卡得独自放下一层的全部四个专家；$V=1,P=2$ 则要一张卡放下两层、每层两个专家；两者都超过 $M=79$（$4\times20=80$）。能负担的 $P$ 只有两个：

- $P=2$（EP 组在节点内）：$H=8$，$X=\lceil12\cdot8/2\rceil=48$，$p_{\mathrm{in}}=1$，$p_{\mathrm{out}}=0$，$x=\lceil48/10\rceil\cdot100=500$；$m_\ell=\lceil12/2\rceil=6$，`gemm`$=18$。`PSI` 行让每个卡组各持一层，二者之间因此是一条 stage 边界；跨过它，除了两组各自的 AllToAll，不再计任何费用。
- $P=4$（EP 组跨节点）：$X=\lceil12\cdot8/4\rceil=24$，$p_{\mathrm{in}}=1$，$p_{\mathrm{out}}=2$，$x=\max(\lceil24/10\rceil,\lceil2\cdot24/1\rceil)\cdot100=4800$；但 $m_\ell=\lceil12/4\rceil=3$，`gemm`$=9$。此时 $V=1$：所有层都在唯一卡组的同一块里，根本不存在层边。

$P=4$ 把每 rank 负载减半（`gemm` 从 18 降到 9），却让每次 AllToAll 从 500 涨到 4800。**这是本题最常见的取舍**：加大专家并行总能省下计算，但省下的计算值不值得多出来的跨节点流量，要看 $B_{\mathrm{in}}/B_{\mathrm{out}}$ 和通信计算比。两种 $P$ 都装得下：$P=2$ 时一个 stage 拥有一层，每卡放 $E/P=2$ 个专家（40 字节）；$P=4$ 时每卡每层 1 个专家、两层共 40 字节，都远低于 $M=79$。
