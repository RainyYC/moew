## `mini` 的重建说明

题面 §3.2 只给出了**输出**（`V P D` / `PSI` / `MAP` / 四条前向调度），没有给输入。
按题面 §3.2「每层恰好有第 4.1 节的十个操作」与 §4.7 的合法性约束，只有 4 个前向
操作的表**不是**一份完整映射（缺 `s_bwd / comb_bwd / gemm_dx / gemm_dw / disp_bwd /
s_dw`），会被判题核心按 `missing` 拦下。

为了让 `mini` 既是一份**完整合法**的映射、又保持题面给的 `Time=180`，`mini.in`
取 §7.1 的参数并做两处必要调整：

* `nmb=1`（§3.2 的表只排了一个 microbatch）；
* `α×=β×=0`（反向的六个操作时长为 0；否则 `comb` 在 180 结束，反向必然把
  Time 推到 180 之后）。

`mini.out` = §3.2 的四条前向行 + 在 `t=180` 挂上六个零时长反向条目，
`Time = 180`（`16 + 70 + 24 + 70`）与题面一致。

## 内存量的一处题面内部冲突（记录在案）

`expected.json` 只锁 `time` 与 `lb`（这两个量决定排名与验收）。`groups` 里的
`Movl` 按 CONTRACT §6 / 题面 §4.6 的**闭区间**规则算：一次传输恰好在下次开始时结束
要算两块（否则「留出空隙的调度是用一单位时间换一块内存」这句就不成立）。

因此 `ex1` 的 `Movl = 2·U`（8 次 AllToAll 首尾相接），而题面 §7.1 的行文写的是
“再加 `Movl=1` 块缓冲”——那是行文的正估值（CONTRACT §1 的示例也沿用了它）。
两者都远小于 `M=39`，不影响合法性，也不影响 `Time`。
