# 参考实现 algorithm_v5 与 Python 移植：对照实验

> 2026-10-30。目的：搞清楚「同一套算法，C++ 与 Python 差多少」，以及参考实现
> 相对本项目的真实优势来自哪里。
>
> - 参考实现源码：`algorithm_v5/`（C++17，含设计/验收文档与逐例汇总）
> - Python 移植：`py5/`（逐行翻译，含冒烟测试）
> - 原始产物：`algorithm_v5/results/final/summary.tsv`、`py5/result_all.json`、`py5/result_cap.json`

## 1. 参考实现做了什么

四层结构，全部与具体机器无关：

1. **精确整数模型**：全链路 `__int128`，含最终时间戳输出；合法性判定不碰浮点。
2. **搜索**：枚举所有合法 `P`；对每个 `P` 用**连续分段 DP** 枚举**全部** `V`
   （`O(V·L²)`，代价函数是每块的计算/通信工作量与单 microbatch 内存约束）。
3. **探针**：每个内存可行的 `P` 先跑一次便宜的事件调度，按**实际 Time**（不是下界）排序。
4. **深搜**：前两名 `P` 才展开窗口 × 优先级 × 通信缓冲 × 镜像布局 × 边界移动。

调度器本身的关键是两条，本项目此前都没有：

- **激活额度预约准入**：开新 microbatch 前向每个卡组预约 `n_g` 个名额，
  $\forall g:\ \mathrm{remaining}_g \ge n_g$ 才准入；`s_bwd` 开始后 $t+1$ 归还。
  这比"固定窗口 $W$"强：并发度由每卡组的激活额度动态决定，而不是一个全局数字，
  且**从构造上不会死锁**。
- **通信缓冲 $b_g\in\{0,1,2\}$**：$b=2$ 允许正时长通信无缝衔接（闭区间峰值 ≤ 2 块），
  $b=1$ 强制 +1 冷却；全零通信组 $b=0$（官方口径不计缓冲）。

## 2. 翻译忠实度

Python 移植（`py5/event_sched.py` + `py5/solver.py`）与原实现逐行对应，
包括不稳定的排序语义、`caps` 的 `min(avail/Ua, mb*ng)` 截断、边界移动只试 3 个切点等。

对拍结果：

| 集合 | 结果 |
| --- | --- |
| 六个官方样例 | 560 / 5240 / 6536 / 3200 / 440 / 1828，与 C++ **逐位相同** |
| 官方 50 例 | **46/50 逐位相同** |
| 4 例差异 | `r20 −48K`、`x04 +356K`、`x11 +36K`、`x12 −350K`，最大 1.4%，**双向** |
| 合法性 | 50/50 通过本地判题器 |

4 例差异来自 C++ `std::sort` 不稳定导致的等价负载 tie 顺序不同（影响 LPT 放置与切点），
不是语义差异。

## 3. 速度差距

| 指标 | C++ | Python 移植 | 倍数 |
| --- | ---: | ---: | ---: |
| 50 例总墙钟 | **29.4 s** | 544.6 s | 18.5× |
| 单例均值 | 0.589 s | 10.9 s | 18.5× |
| 单例最大 | 2.577 s | 42.6 s | 16.5× |
| 超 10 s 的用例 | 0/50 | 27/50 | — |

墙钟倍数中位 18.8×、几何 18.7×，范围 14.5–23.1×。

## 4. 关键结论：C++ 几乎不带来质量收益

由于 Python 版有 27 例超过 10 s，实测了"给它 9 s 预算会掉多少"：

| 版本 | 均值 `TIME` | 合法 | 相对 C++ |
| --- | ---: | --- | ---: |
| C++（无时间预算） | 20,621,198 | 50/50 | — |
| Python（不限时） | 20,621,085 | 50/50 | −0.001% |
| **Python（9 s 限制）** | **20,635,372** | 50/50 | **+0.069%** |

限时只改变 **5/50** 例（`x12 +1.53%`、`x04 +0.43%`、`x15 +0.40%`、`r20 +0.18%`、
`r24_p4 +0.14%`），其余 45 例逐位相同。

**解释**：受限时砍掉的是 rich 深搜（上百次完整调度），而真正决定质量的三步——
按 `V` 的切层 DP、专家放置、每个 `P` 一次的探针调度——Python 在 9 s 内仍跑得完。

因此：

- **算法质量上，C++ 的收益 ≈ 0**（+0.069%）。
- C++ 的收益在**工程性质**：固定候选集、无时间预算、结果不受机器负载影响。
- 参考实现领先本项目的 4.9%，**全部来自调度器**（预约准入 + 缓冲建模），
  与语言无关——单次调度在 Python 里也只要 20–40 ms。

## 5. 参考实现相对本项目的强弱

| | 均值 `TIME` | 说明 |
| --- | ---: | --- |
| 本项目（master，含就绪前沿调度） | 21,627,400 | — |
| 参考实现 v5 | **20,621,198** | 快 4.9%，37 胜 / 4 平 / 9 负 |

参考实现**更强**的用例集中在计算主导的大例（`x02 −18.0%`、`r64_v8_c8b −16.8%`、
`x08 −16.7%`、`x15 −16.4%`）；这些用例双方选的 `V/P/K/ψ` **完全相同**，
差距来自调度：同一配置下参考实现的 `Time/lb` 是 1.05–1.27，本项目是 1.20–1.48。

参考实现**更弱**的地方是可穷举的小用例——它没有 `nmb=2` 精确分支：

| 样例 | 参考实现 | 本项目 |
| --- | ---: | ---: |
| ex2 | 5,240 | **4,880** |
| ex3 | 6,536 | **6,072** |
| ex5 | 440 | **416** |
| ex6 | 1,828 | **1,696** |

## 6. 可复现

```bash

cd algorithm_v5 && ./build.sh && ./run_acceptance.sh final

# Python 移植（对拍用）
cd py5 && python3 smoke.py                       # 内核冒烟测试
python3 solver.py ../data/official/Problem/cases/x08_lr_lowb_p4.txt /tmp/x08.out
python3 run_all.py 300                           # 全 50 例，记录 Time 与墙钟
python3 run_cap.py 9.0 40                        # 9 s 预算版
```

三处入口都需要 `data/official/Problem/cases/`（官方包，未入库）。
