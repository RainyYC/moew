## 结论

1. **先修 `r64_v8_c8a`。** 它离当前布局资源界 8.28 倍，远大于其他 top 案；内存只允许很窄的激活重叠。尝试双 microbatch 交错并显式限制 activation 峰值为 2，别让 heuristic 为更多并发付出 buffer / activation 超额。
2. **再扫 P，不要默认 P=1。** `x15`、`r32`、`x07`、`x08`、`x13`、`x10`、`x12` 的当前 P=1/2 均明显落后于另一合法 P 的乐观界。对每个候选 P 实际生成 schedule 后再比 Time；下界差距说明值得尝试，不保证替代 P 最终获胜。
3. **`x01` 与 `x06` 是 schedule 优化样本。** 前者 P 已是最优下界候选，先填计算气泡；后者内存宽松，优先紧凑 stagger，再测 P=2。
4. `x12` 的实际 MAP 与组层工作已经很接近当前 P 的下界；进一步收益主要靠尝试 P=5 和压 CP / 引擎空闲，而不是大幅换 MAP。

这些下界是性能诊断，不是已知最优成绩；`Time/RLB` 表示理论优化空间，不代表一定能达到 1.0。
