## 特征分组与优化重点

- **计算侧 / 相对均衡（乐观每层 `x/max(s,gemm)` < 0.75）**：r16_p4_trap.txt, r20_p2_flat.txt, r24_p3_flat.txt, r24_p4_block.txt, r32_p8_ramp.txt, x01_lr_block_p2.txt, x02_lr_ramp_c16.txt。优先投入切层与并行 pipeline 排法；单纯提高 P 往往只压低 `gemm`，使通信占比更高。
- **通信强 / 关键对端带宽（比值 > 2）**：r128_v4_c4a.txt, r128_v8_c4.txt, r256_v4_c4.txt, r256_v8_c16.txt, r256_v8_c4.txt, r256_v8_c8a.txt, r64_v4_c4d.txt, r64_v8_c16a.txt, r64_v8_c16b.txt, r64_v8_c8a.txt, r64_v8_c8c.txt, r64_v8_c8e.txt, r64_v8_c8g.txt, x04_lr_inter_p5.txt, x08_lr_lowb_p4.txt, x10_lr_tight_p8.txt, x11_lr_deep_p3.txt, x12_lr_close_p10.txt, x13_lr_twochunk_p8.txt, x14_lr_twochunk_p15.txt, x15_lr_twochunk_p10.txt, x16_vl_trap4_ramp.txt, x17_vl_tight_block.txt, x18_vl_tight_small.txt, x19_vl_trap4_fs4.txt。优先避免把 EP 组铺到跨节点；网格的 `P` 应按 p_in/p_out 与带宽比较。典型强通信 `x` 家族包括 `x04/x10/x11/x12/x14/x18`。
- **过渡组（0.75..2）**：r128_v8_c8a.txt, r128_v8_c8b.txt, r64_v2_c2.txt, r64_v2_c4.txt, r64_v4_c4a.txt, r64_v4_c4b.txt, r64_v4_c4c.txt, r64_v4_c4e.txt, r64_v8_c16c.txt, r64_v8_c8b.txt, r64_v8_c8d.txt, r64_v8_c8f.txt, x03_lr_trap_p3.txt, x05_lr_tight_p6.txt, x06_lr_trap_p7.txt, x07_lr_flat_p10.txt, x09_lr_skew_p6.txt, x20_vl_flat_control.txt。以实测/估算引擎负载选 P，不宜用单一固定宽度。
- **显式热点映射优先**：上述偏斜案例里，`m_l` 是 MAP 约束下的最大 rank-slot 汇总，而非 `ceil(T/P)`。先用每 rank 专家数固定为 `E/P` 的热点分散/贪心装箱，衡量 `m_l` 收益；通信仍只看 T。
- **两块切分重点**：`VPP_possible` 在 JSON 中指出可行 `2V<=L` 范围；它能让每组持有首尾各一块并利用双向流水，但静态参数层数仍计入同一组，需要将 VPP 与 K=V 的切分做实际内存 / makespan 比较。

## 内存与数值核对

- JSON 的候选可行范围按 `ceil(L/V)*((E/P)*Z+Zs+Uact) + U <= M` 计算。`K=V` 均匀切层时，这也是可由逐个 microbatch 串行前后向达到的内存安排；对 `P=1`，官方checker不为零时长通信计 buffer，因此下界实际可省略 `U`，本批筛选已计入该例外。`K=2V` 的同类筛选仅按每组层数做内存必要条件，仍需完整排程复核。
- 每案、所有合法 P 与层，对 `s_bwd`、通信反向、`gemm_dx/dw`、`s_dw` 比较了精确有理数 ceil 与官方 checker 的 float ceil；本批 **0 个差异**。最大候选 operation base duration 为 `864000`，该范围未触发浮点进位差异。
- 样例参数含 P=1 的免通信结构，但数据并非全通信主导。`x20_vl_flat_control`、`x07_lr_flat_p10`、`r20_p2_flat` 是明显均衡控制组；`x09_lr_skew_p6`、`x03_lr_trap_p3`、`x06_lr_trap_p7` 与 `x16/x19` 是偏斜 / 热点装箱压力组。

## 下界解读

`lower_bounds.json` 给出每案跨 P 最小的通用乐观下界（本批从 `974016` 到 `99380736`），以及每个 P 对应的 K=V 连续切层 DP 工作量参考值。通用下界同时适用于 K=V 与 K=2V；DP 只对应 K=V，不代表已知最优成绩或 K=2V 的下界。实现者可用它检查 schedule 的 TIME 是否接近由总引擎工作量、单层工作量或单microbatch依赖链决定。

## 优先实施建议

1. 先让网格搜索针对每案快速枚举合法 P，算精确 p_in/p_out、x；遇 P=1 时直接走 x=0 分支。
2. 按参数内存下界剪枝 V，并为完整调度留下 buffer 与 activation 峰值余量；VPP 需要额外检查 `2V<=L` 与镜像卡组驻留。
3. 热点案先优化 MAP；均衡案避免做昂贵 MAP 搜索。
4. 对主要通信路径优先保持网络引擎不空闲，并让共享专家 `s` / `s_bwd` 与对应通信重叠；计算权重梯度可推迟至 `comb_bwd` 后的计算空档。
5. 输入时间尺度偏小到足以令本批精确/float ceil 一致，但实现时仍宜用 128 位整数和精确有理数 ceil，避免泛化溢出 / 浮点误差。
