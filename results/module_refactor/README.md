# 模块重构验收记录

本次将维护源码拆为 25 个头文件与一个编译入口，统一 operation 枚举、节点编码和 DAG 边定义，封装 grouped placement 搜索状态，并保留可独立提交的 `submission/solver.cpp`。算法候选顺序、数值运算、邻域、接受规则和截止预算保持不变。源码提交为 `b6f107a989327f34b5767b744c9a1ac54dbfc2b7`，具体设计见 [模块说明](../../docs/module-design.md)。

## 构建与确定性

- [头文件检查](header_checks.json)：25/25 个头文件可独立通过 C++17 语法检查。
- 模块入口和导出单文件均使用 `g++ -std=c++17 -O2 -pipe -Wall -Wextra` 编译，无警告；两个二进制逐字节相同，SHA-256 为 `09a283409f48c7c06bb8e9d7f3fc2ac62c7ce7cf3f69628cb083e5f1235475b8`。
- `make submission-check` 通过；单文件导出与当前模块源码一致。
- 维护入口是 `src/solver.cpp`，裁判单文件是 `submission/solver.cpp`。构建仍只有一个翻译单元，没有增加动态分派。

## 固定工作量对照

[第一组记录](fixed_work/validation.json)覆盖 `r128_v4_c4a`、`r16_p4_trap`、`x01_lr_block_p2`、`x10_lr_tight_p8`、`x12_lr_close_p10`、`x20_vl_flat_control`。每个版本、每例运行两次，交换先后顺序，共 24 次；均使用 `--polish-pass-limit=24`。

所有配对 stdout 字节和非时间搜索计数完全相同，六例均通过官方 grader。拆分前 CPU 总量为 42.244343 秒，模块版本为 41.997571 秒，变化 −0.584%。CPU 通过每次求解器子进程的用户态、内核态耗时之和计算，不含随后执行的 grader。

补充的 `r24_p3_flat` 固定 8 轮对照共四次，stdout 与非时间计数也完全相同；CPU 总量从 17.866198 秒到 17.677955 秒，变化 −1.054%。两组实验未观察到固定工作量整体变慢；样本有限，这些小幅变化不应解释为确定的加速保证。

## 三个差异点的同机交替复测

用 [复测脚本](../../scripts/paired_recheck_module_refactor.py) 对三例分别执行拆分前→模块版本、模块版本→拆分前，两轮共 12 次，**不传搜索轮数限制**；另附上文固定 8 轮四次。全部 16 次合法且无超时。CPU 密集的求解器任务串行执行，期间不并行编译、浏览器渲染或其他验收。完整记录在 [runs.json](paired_recheck/runs.json)，对照见 [comparison.json](paired_recheck/comparison.json)。

| 用例 | 拆分前第 1 / 2 次 | 模块版本第 1 / 2 次 |
|---|---:|---:|
| r24_p3_flat | 22,118,210 / 22,118,210 | 22,088,422 / 22,101,510 |
| x09_lr_skew_p6 | 17,164,896 / 17,164,896 | 17,164,896 / 17,147,936 |
| x12_lr_close_p10 | 27,946,170 / 27,967,350 | 27,968,079 / 27,959,850 |

拆分前二进制也不能稳定复现历史单次结果。日志中固定搜索前缀相同，截止前完成的 extension 轮数不同；新旧胜负随运行而变化。这支持差异主要来自按墙钟截止的搜索波动，不能将单次默认预算分数差直接归因于模块化，也不能保证每次分数完全相同。性能判断以固定工作量对照为主要依据，而非两个版本都用满预算时相近的总 CPU。

初次误传显式 24 轮上限的试跑已中止，单独保存在 `paired_recheck/explicit_pass24_interrupted/` 并注明；不计入默认预算复测，也不用于选择最终成绩。

## 可复核文件

从仓库根目录执行 `sha256sum -c results/module_refactor/full50/SOURCE_SHA256SUMS` 可检查提交的源码、报告、图表和验收汇总。`SHA256SUMS` 另记录本地二进制和逐次答案、日志；这些运行产物依仓库规则不上传 Git，可通过记录的命令重建，但按时间截止的结果可能波动。

拆分前源码及文档快照在 `backup/before-module-split/`。历史校验清单仅将已变化的路径转向内容相同的快照，原始源码和成绩的 hash 没有改写。
