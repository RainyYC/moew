## 1. 结果摘要

本解将网格选择、专家放置、连续切层和双引擎调度组织成一个分层搜索流程：先让每个可行专家并行规模 P 都接受一次完整调度评估，再对表现最好的候选进行更细的策略搜索。核心收益来自计算与通信重叠、microbatch 流水执行，以及通过参数内存与激活内存的联合权衡选择 P。

## 2. 问题建模

求解器需要同时输出四部分决策：

1. 网格 `(V,P)`：流水线卡组数与每组专家并行规模。
2. 连续块切点 `PSI`：块数 K 为 V 或 2V。
3. 每层专家到 rank 的映射 `MAP`：每个 rank 恰好持有 E/P 个专家。
4. 全部 `(microbatch, layer, operation)` 的开始时刻 `SCHEDULE`。

目标是最小化所有操作的最晚完成时刻：

\[
\operatorname{Time}=\max_o(t_o+d_o).
\]

约束包括操作依赖、每卡组计算/通信引擎各自互斥，以及每卡参数、通信缓冲和激活内存限制。网格还需满足：

\[
VP\le NS,\quad P\mid E,\quad (P\mid S\ \text{或}\ S\mid P),
\quad 1\le V\le\min(L,64).
\]

本题不对层间 PP 边界额外收取传输时间。因而不能套用另一个带跨 stage 传输成本的模型，也不能将 K=2V 理解成可以反转一半 microbatch 的层序：所有 microbatch 的前向均按层号递增执行。

### 2.1 精确操作时长

给定每层专家映射，计算每个 rank 的负载，并取最重者：

\[
m_\ell=\max_r\sum_{e:\sigma_{\ell,e}=r}a_{\ell,e},
\qquad g_\ell=m_\ell F_{\mathrm{in}},
\qquad s_\ell=T_\ell F_{\mathrm{s}}.
\]

通信量及通信时长为：

\[
H=\left\lfloor\frac{db}{k}\right\rfloor,\quad
X_\ell=\left\lceil\frac{T_\ell H}{P}\right\rceil,
\]

\[
p_{\mathrm{in}}=\min(P,S)-1,\quad
p_{\mathrm{out}}=P-1-p_{\mathrm{in}},
\]

\[
x_\ell=F_{\mathrm{io}}\max\left(
\left\lceil\frac{p_{\mathrm{in}}X_\ell}{B_{\mathrm{in}}}\right\rceil,
\left\lceil\frac{p_{\mathrm{out}}X_\ell}{B_{\mathrm{out}}}\right\rceil
\right).
\]

| 操作 | 引擎 | 时长 |
|---|---|---:|
| s | 计算 | sℓ |
| disp、comb | 通信 | xℓ，各一次 |
| gemm | 计算 | gℓ |
| s_bwd | 计算 | ⌈αsℓ⌉ |
| comb_bwd、disp_bwd | 通信 | ⌈αxℓ⌉，各一次 |
| gemm_dx | 计算 | ⌈αgℓ⌉ |
| gemm_dw | 计算 | ⌈αβgℓ⌉ |
| s_dw | 计算 | ⌈αβsℓ⌉ |

实现使用 `__int128` 计算关键时间、负载、内存及 DP 数值，并输出整数时间戳。反向系数用微单位整数计算，权重梯度直接对完整乘积向上取整，不做两次取整。

省略专家负载向量时，将 Tℓ 尽量均分到 E 个专家，再按实际 MAP 汇总 mℓ。共享专家时长 `Tℓ*Fs` 已由官方判题器确认。该批 50 例中，精确整数公式与官方判题器的浮点系数计算没有产生时长差异。

## 3. 总体算法

最终代码采用以下流程。这里的“基础评估”使用全部 microbatch，不是缩小实例后的估计。

```text
读取实例，重建每层专家负载
对每个合法 P：
    构造等数量专家映射，并执行成对交换改进
    枚举合法 V，用内存约束连续分段 DP 生成切层
    保存代理代价最优的 V，以及最大可行 V
    对最大可行 V 的布局运行一次完整事件调度

保留所有 P 的基础评估中的最优解
按实际 Time 选出前两个 P：
    比较三种优先级、多个窗口和两类缓冲策略
    对基础评估第一名 P，额外比较镜像布局与局部切点扰动
    只在实际 Time 更小时替换当前解

按时间顺序输出完整 MAP、PSI、SCHEDULE
由官方 grader 在验收阶段检查最终输出
```

基础评估对有通信的组采用一块缓冲预算，全零通信组采用零缓冲预算。增强搜索再加入允许连续衔接的双缓冲策略。这个实现细节比“自动缓冲”这一概括更准确。

搜索是固定、有界的候选组合，没有内部 7 秒截止计时器。最终 50 例的 10 秒限制由验收脚本执行，全部实际运行均满足限制。

## 4. 专家放置：等容量装箱与局部交换

固定 P 后，专家放置不会改变通信量，也不会改变每层每卡的参数大小；它主要通过 mℓ 影响三个路由专家计算操作。因此先优化每层 MAP，再让实际调度评估它的收益。

初始映射使用带数量约束的 LPT：按专家负载从大到小，依次放入尚未装满、当前总负载最小的 rank。容量为 E/P，不能只均衡负载而忽略专家数量。

随后至多进行六轮成对交换。每次交换来自两个不同 rank 的专家，保持数量不变；按以下目标选择改进：

\[
\left(\max_r L_r,\ \sum_r L_r^2\right)
\]

按字典序最小化，优先降低最重 rank，再降低负载平方和。若达到

\[
\max\left(\left\lceil T_\ell/P\right\rceil,\max_e a_{\ell,e}\right)
\]

这一负载下界，可提前停止。最终操作时长始终由选中 MAP 的真实最重 rank 计算，不用平均负载代替。

固定 50 例中有 35 例含显式偏斜负载，因此这一步对候选比较有实际意义。但成对交换仍是局部搜索，不保证求得最优等基数划分。

## 5. 切层与镜像布局

### 5.1 连续分段动态规划

固定 P、V，将前 i 层切成 j 个非空连续块。用前缀和计算区间代理工作量，递推为：

\[
DP[j][i]=\min_h\max\bigl(DP[j-1][h],\widehat W(h,i)\bigr).
\]

转移必须同时满足区间参数与至少一个完整 microbatch 的激活驻留条件。记录最优前驱后恢复切点。

**最终实现的 DP 代价是加权代理工作量，不是精确 makespan。** 它以 `ceil(Tℓ/P)` 估计路由专家计算，设据此得到的计算总量为 Ĉℓ、通信总量为 Dℓ，前向路由计算为 ĝℓ，则层权重可写成：

\[
\widehat w_\ell=\widehat C_\ell+D_\ell+
(s_\ell+\widehat g_\ell+2x_\ell).
\]

额外一份前向工作量用于偏重前向路径。区间代价为这些层权重之和。该近似只用于生成布局；真实 MAP 与完整事件调度决定最终胜负。它与初始设计中“直接平衡计算、通信两种负载的最大值”存在实现差别，不能混为一谈。

### 5.2 K=2V 与切点扰动

除 K=V 外，增强搜索测试有限个镜像组数。块 k 的归属为：

\[
g(k)=\begin{cases}k,&k<V,\\2V-1-k,&k\ge V.\end{cases}
\]

镜像块从均匀切点开始，同组两块共用参数预算、计算引擎和通信引擎。随后选择最多三个相邻层工作量差较大的边界，分别尝试移动一层；保持块非空，并重新运行完整调度。

这里没有穷举所有镜像深度、切点组合或连续多轮移动。镜像布局只是候选，只有最终 Time 变小时才采用。

## 6. 受内存约束的双引擎事件调度

### 6.1 DAG 与可重叠结构

每个 `(mb,ℓ)` 有十个节点。层内主要依赖为：

```text
disp → gemm ─┐
s ──────────┴→ comb

comb_bwd → gemm_dx ─┐
s_bwd ─────────────┴→ disp_bwd

comb_bwd → gemm_dw
comb_bwd → s_dw
```

此外，本层 `s_bwd`、`comb_bwd` 均要等待本层 `comb`。前一层 `comb` 释放本层 `s/disp`，后一层 `disp_bwd` 释放本层 `s_bwd/comb_bwd`。

这使共享专家前向可以藏在分发通信下，共享专家输入梯度可以藏在反向汇集下。两个权重梯度不阻塞上一层输入梯度，可以用于填补计算引擎空闲。

### 6.2 内存预算

每卡每层参数大小为

\[
q=(E/P)Z+Z_s.
\]

若组 g 持有 n_g 层、为通信保留 b_g 块缓冲，则激活名额为

\[
A_g=\left\lfloor\frac{M-n_gq-b_gU}{U_{\mathrm{act}}}\right\rfloor.
\]

三类通信策略为：

| b_g | 适用条件与规则 |
|---:|---|
| 0 | 该组通信全部为零时长；不占通信缓冲，不加冷却间隔 |
| 1 | 正时长通信之间至少隔一个整数时间单位，避免交接端点计两块缓冲 |
| 2 | 正时长通信可在前一个结束时立即启动，交接点最多计两块缓冲 |

即使正时长操作不能同时占用通信引擎，首尾衔接时的缓冲峰值仍可为 2。这是内存统计与引擎互斥的不同端点规则。

### 6.3 安全激活预约

准入一个新 microbatch 前，向每个组预约 n_g 个激活名额；所有组都能满足才准入。对于已经准入的 microbatch，它完成整个前向所需的激活容量已经有保证，不会中途因尚未取得后续激活空间而无法推进。

每个激活从 `comb` 结束到 `s_bwd` 开始按闭端点计费，所以在 `s_bwd` 于 t 启动后，要到 t+1 才归还预约名额。

由于尚未产生的激活也有预约，实际活跃激活数量不超过预约数量，因而

\[
n_gq+b_gU+A_gU_{\mathrm{act}}\le M
\]

可以保证该策略下的内存安全。该方法易于验证，但较保守：它可能限制本来可以通过更细粒度内存分配实现的并发。

### 6.4 事件处理与三种优先级

每组维护计算、通信两个就绪队列；全局事件队列记录操作结束与预约名额归还。先处理当前时刻的完成事件，再启动可运行节点。零时长节点立即完成，继续释放同刻后继，直到无新操作可启动；随后跳到下一完成事件或通信冷却结束时刻。

实现比较三种确定性策略：

| 模式 | 主要规则 |
|---|---|
| A：反向优先 | 优先输入梯度，其次推进已有前向，权重梯度填空；同类偏好较旧 microbatch |
| B：关键路径优先 | 按反向、前向、权重梯度分组，再参考 DAG 最长剩余路径排序 |
| C：动态配对优先 | 每次从最多 16 个就绪候选中选择；优先完成 `s/gemm` 或 `s_bwd/gemm_dx` 中已完成一半的组合，以尽快解锁通信 |

模式 C 在激活额度紧张时也提高 `s_bwd` 的优先级。三种模式均作为候选竞争，不假定某一种对所有实例都最好。

额外窗口候选为 `{1,2,V,2V,无限制}`，重复值去重；“无限制”仅取消额外窗口限制，激活预约仍然生效。全部操作最终按开始时刻排序，每个操作单独一行，包括零时长操作。

## 7. 最重要的搜索修订：不能过早淘汰 P

初版增强搜索没有让所有 P 都接受完整事件调度，因而可能错过一个通信稍慢、但激活容量大得多的布局。静态计算量或通信量下界不能反映这一收益。

典型案例 `r64_v8_c8a` 的参数包括：

| 参数 | 值 |
|---|---:|
| 总卡数 / 层数 / 每层专家数 | 64 / 16 / 64 |
| 每卡内存 M | 34,603,008 字节 |
| 单专家参数 Z | 1,048,576 字节 |
| 单通信缓冲 U | 699,051 字节 |
| 单激活 U_act | 159,159 字节 |
| microbatch 数 | 32 |

当 P=2、V=16 时，每卡参数占 32 MiB，扣除一块通信缓冲后仅能容纳 2 份激活。P=4 时，每卡参数降为 16 MiB，获得大幅增加的激活空间；增加的通信成本被流水线并发收益抵消。

| 配置 | 官方 Time |
|---|---:|
| 修订前选择 P=2 | 28,486,584 |
| 修订后自动选择 P=4 | **5,282,831** |

该例加速约 **5.39 倍**。最终策略要求每个可行 P 都先完成一次全量调度比较，再对实测前两名深搜。相对保存的搜索修订前快照，50 例中 **21 改善、29 持平、0 回退**，几何平均加速为 **1.1768 倍**。

## 8. 复杂度与工程取舍

设合法 P 的数量为 Q，操作总数为 `J=10*n_mb*L`，实际评估的调度候选数为 B。

| 模块 | 复杂度或主要开销 |
|---|---|
| 单 P 专家映射 | 每层排序、容量装箱及至多六轮成对交换，约 O(L(E log E + EP + 6E²)) |
| 单个 V 的切层 DP | O(VL²)，空间 O(VL) |
| 当前实现枚举全部 V | 每个 P 重建各 V 的 DP，合计 O(Vmax²L²) |
| 一次事件调度 | DAG 与队列存储 O(J)；堆操作和输出排序约 O(J log J)，另有每轮扫描 V 组的开销 |
| 动态配对候选 | 每次最多检查 16 个候选，避免扫描全部就绪节点 |
| 全部搜索 | 多个 P 的预处理，加 B 次事件调度；B 由固定候选集合限制 |

当前调度器每轮会扫描各组，不能把整份实现严格描述为完全消除了 V 因子的 O(J log J)。在指定数据集上，实测最慢 2.577 秒，满足要求。

尚未实现的增强项包括：精确多路专家划分、完整镜像切点搜索、全部边界反复迭代，以及只在已知空档足够长时才启动权重梯度的等待策略。更大的未见实例也没有内部截止机制提供的运行时保证。

## 9. 成绩口径与历史算法比较

### 9.1 两个指标分别计算

算术平均 Time 为：

\[
\overline T=\frac1{50}\sum_{i=1}^{50}T_i.
\]

相对官方 Python 样例解的几何平均比值为：

\[
G=\exp\left(\frac1{50}\sum_{i=1}^{50}
\log\frac{T_i}{T_i^{\mathrm{Python\ sample}}}\right).
\]

两者都越低越好，但不是同一个数，也不是百分制分数。本解的 `20.621M` 指前者，`0.678538` 指后者。

### 9.4 串行保底对照的正确含义

本次保留的早期串行快照平均 Time 为 360,711,578.20。最终版相对它的几何平均加速为 15.30 倍，50 例全部改善。

这不是相对历史主线的提升。两类比较必须分开：

* 对本次早期串行快照：**逐例加速比的几何平均为 15.30 倍**。

## 10. 验收、实现边界与后续方向

最终验收直接复用官方 grader，没有重新设计判题器。保存了每个输入的输出时间表、求解器日志、判题器日志以及 `summary.tsv`。事件调度模块另有冒烟驱动，检查操作完整性、DAG 依赖和零时长处理；本报告不将它描述为全面边界测试或最优性证明。

官方语义中特别影响实现的两点是：

1. 零时长通信不占引擎，也不计通信缓冲；仍必须输出对应操作。
2. 正时长通信的交接端点及激活释放端点计入内存峰值，激活不能在释放同刻立刻复用预约名额。

继续优化可优先考虑：以实际 MAP 负载重构 DP 代价、细化激活预约以减少保守限制、增加权重梯度的空档判断，以及将固定候选搜索改成有明确截止机制的预算分配。每项改动都应保留当前最好结果，用完整调度与官方判题验证收益。
