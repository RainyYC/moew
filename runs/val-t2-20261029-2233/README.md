## 1. 规则（2026-10-29 版的关键点）

完整文本见 `problem-v4.md`。相对更早版本有三处实质变化，**都已落实**：

### 1.1 输出格式

```text
V P
PSI
K ψ_1 ... ψ_{K-1}
MAP                       （L 行，每行 E 个整数）
SCHEDULE
t mb:ℓ:op mb:ℓ:op ...
```

首行只有两个数（旧的 `V P D` 已废）。`K` 只能取 `V` 或 `2V`；`K=1` 时 `PSI` 行只写 `1`。

### 1.2 网格：`V·P ≤ R`（不是 `= R`）

> 若 `V·P < R`，则只有前 `V·P` 张卡承载层，其余 `R−V·P` 张空闲——不执行操作，也不计内存。

**这是重要自由度**：卡是"免费"的。`P` 同时决定计算量（`gemm = m·F_in`，`m` 随 `1/P` 降）与通信量
（`X = ⌈T·H/P⌉`，`p_in/p_out` 由 `P` 与 `S` 的关系决定）；`V` 决定流水线深度与填充代价 `(nmb+V−1)/nmb`。

**本项目已验证的策略**：`V` 取最大 `min(L, 64, R//P)`（乘积 `(nmb+V−1)/V` 对 `V` 单调递减）；
`P` 一般取**最小合法值**（`P=1` 时没有 EP 对端、`x=0`，通信整条消失），唯一例外是"负载均衡 + 计算主导"
时 `lb` 对 `P` 变平（此时填充决定胜负，取最大 `P`）。

### 1.3 十种操作与依赖（`§4.2` 原文，逐条实现）

| 操作 | 引擎 | 时长 |
| --- | --- | --- |
| `s` | 计算 | `s_ℓ = T_ℓ·F_s` |
| `disp` | 通信 | `x_ℓ` |
| `gemm` | 计算 | `m_ℓ·F_in` |
| `comb` | 通信 | `x_ℓ` |
| `s_bwd` | 计算 | `⌈α·s_ℓ⌉` |
| `comb_bwd` | 通信 | `⌈α·x_ℓ⌉` |
| `gemm_dx` | 计算 | `⌈α·m_ℓ·F_in⌉` |
| `gemm_dw` | 计算 | `⌈αβ·m_ℓ·F_in⌉` |
| `disp_bwd` | 通信 | `⌈α·x_ℓ⌉` |
| `s_dw` | 计算 | `⌈αβ·s_ℓ⌉` |

其余量：

```
H  = ⌊d·b/k⌋
X  = ⌈T·H / P⌉                       ← 每个对端的字节数（不是总量！）
x  = max(⌈p_in·X/B_in⌉, ⌈p_out·X/B_out⌉) · F_io
```

**依赖表（2026-10-29 版，必须逐条对上）**：

| 操作 | 前驱 |
| --- | --- |
| `s` | —（跨层：等上一层 `comb`） |
| `disp` | —（跨层：等上一层 `comb`） |
| `gemm` | `disp` |
| `comb` | `gemm`, **`s`**（共享专家前向须在汇集之前收尾） |
| `s_bwd` | `comb`（跨层：等下一层 `disp_bwd`） |
| `comb_bwd` | `comb`（跨层：等下一层 `disp_bwd`） |
| `gemm_dx` | `comb_bwd` |
| `gemm_dw` | `comb_bwd` |
| `disp_bwd` | `gemm_dx`, **`s_bwd`**（反向分发的梯度里有共享专家那份） |
| `s_dw` | `comb_bwd` |

> ⚠️ **踩过的坑（务必保留这个认知）**：共享专家"与同层解耦"**不等于**完全自由。漏掉
> `comb ≥ s`、`disp_bwd ≥ s_bwd`、`s_dw ≥ comb_bwd` 这三条，模型会**退化**并给出"更好"的假结果
> —— `ex2` 会掉到 3200、`ex3` 掉到 4000，恰好都是通信引擎下界。详见 `docs/rule-change-1029.md`。

### 1.4 内存（`§4.6`，闭区间口径）

```
Mexp  = Σ_{ℓ∈卡} ((E/P)·Z + Z_s)
Movl  = U · max_t #{在 t 时刻已开始未完成的通信操作}      ← 首尾相接算 2 块
Mact  = U_act · max_t #{在 t 时刻前向已完成、反向未完成的 (mb,ℓ)}
合法性：三块之和 ≤ M
```

零时长操作**不占引擎**；但零长度通信**计入 Movl**（保守口径，可开关），零长度激活**必须计入 Mact**。

## 4. 求解器做了什么

`python3 solver/solve_all.py <case.in> [out]`，单例墙钟 ≤ 1 s（小例）/ 3–7 s（64 万 op）。

```
网格枚举（P → V=max, ψ 候选）
  → 专家放置（LPT + 换位下降）
  → 列表调度（8 种优先级变体 × 2 种出堆模式 × 多档窗口）
  → 引擎序列模拟退火（仅小用例；大用例跳过，因为单次求值 O(n)）
  → 内存核算，超限丢弃
```

四个曾经的真实缺陷（都已修，回归测试在 `solver/selftests/test_tight_window.py`）：

1. **回退路径没有预算** → 64 万 op + 内存紧时永不返回（必然 0 分）。
2. **`prio` 出堆在窗口被压小时把流水线串行化**（利用率 3.16%）→ 改 `early` 出堆，30 倍。
3. **窗口候选逐个枚举到 1000 个** → 改对数刻度 + 窗口探测，b11 从 1.26 降到 1.00。
4. **内存极紧时"其实有解却返回无解"** → 把 `comm_gap` 插入放进主搜索的非法分支。

## 5. 严格程度：什么被证明、什么没有

| 结论 | 证据 | 强度 |
| --- | --- | --- |
| 六例的 Time 是全局最优 | CP-SAT（`tools/cpsat_global.py`），枚举全部决策 | **已证** |
| ex3 = 6072 | 额外的独立穷举（`tools/ex3_verify.py`，317 万种引擎次序，不用 OR-Tools），且复现了题面自己的 `P=4 → 76800` 对照值 | **已证**（两种独立方法） |
| 大用例的 Time 离最优多远 | 只有 `lb` 与解析式上界（填充项），**没有最优性证明** | **未证** |
| "大用例没有优化空间" | 四种搜法都没改进（见 §7） | **经验性**，不是证明 |

> 方法论教训（写在这里避免重犯）：**下界只能按单一来源取 `max`，不能跨来源相加**。早期用
> "头段 + 引擎工作量 + 尾段"相加，因尾段的通信操作已含在工作量里而重复计入 800，得出偏大的
> "有效下界"。详见 `docs/optimality.md` §3。

## 7. 给下一个人的：我认为还值得打的地方

按"期望收益 / 难度"排序。

### 7.1 大用例的最优性证明（最难，但最有价值）

现在大用例只有 `lb` 与填充项，**没有任何最优性证据**。可行的路线：

- 对 `nmb` 小、`L` 中等的实例（如 `nmb=8, L=16`）用 CP-SAT 求解，与启发式对比，找出启发式的系统性损失；
- 构造"可解析求解"的实例族（如 `P=1`、`x=0`、负载均衡），此时问题退化成**同构流水车间**
  （`V` 级、`nmb` 个作业、每级 6 个有固定次序的工序），这类问题的最优 makespan 有理论结果，
  可以拿来做对照。

### 7.2 `P=1` 纯计算型的调度范式（收益预计 <5%，但可证伪）

b01/b12 是 `x=0`、只剩计算引擎的极端情形。现在的排法是列表调度 + 退火，38 秒没有改进。
值得试的是**显式构造 wavefront**：把每个 mb 的 6 个计算操作按"前向 2 个 / 反向 4 个"拆开，
让反向算子专门填充别的 mb 留下的空档（类似 ZB-H1 但更激进）。若能构造出严格更短的排法，
就直接证伪"没有余量"。

### 7.3 `K = 2V`（DualPipe 镜像）从未被使用

当前 `build_plan_from_parts` 恒取 `K = V`。`K = 2V` 要求 `2V ≤ L`，而本项目的策略总是取 `V = L`
（此时无解）。**但如果某个实例的最优 `V` 严格小于 `L/2`，镜像配对可能带来真正的重叠收益**。
值得在 `L` 大、`nmb` 小的实例上专门验证。

### 7.4 网格选择的启发式还很粗

`P` 的选择基于 `lb × fill` 排序 + 逐个尝试；`V` 直接取最大。这是"能证明的方向"，但**没有闭式解**。
如果能量化 `Time(P,V)` 的近似式并对它做全局最小，可能省下几次调度尝试的时间，把预算留给调度质量。

## 9. 已知边界（不要误判）

1. **`Time/lb` 不是质量指标**（除非网格相同）。见 §3 的比值陷阱。
2. **`lb` 是单来源下界，偏松**：ex3 的 `lb=4000` 而真实最优 6072（差 52%）。拿 `lb` 当目标会永远"差一点"。
3. **大用例的最优性未知**：只有六个官方用例被证明最优。
4. **`cases/mini` 不是题面样例**：v4 的 §3.2 只给了前向片段，凑不满十个操作，所以 mini 是本项目自造的
   最小完整例（`Time=164`）。
5. **判题器与求解器共享公式**（`judge/core/model.py` 与 `solver/formula.py` 各写一份，逐项对拍）。
   独立复算器 `tools/independent_check.py` 是第三条实现，改规则时它最先红。
